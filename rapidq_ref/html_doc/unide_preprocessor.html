Preprocessor: missing include files, resources and DLLs

unIDE: RqDeps.pas (scan, search, choice of a copy), DlgRqDeps.pas (window «Недостающие файлы программы»), DlgFindInc.pas (View — Find inc file), IncCheck.pas (disk search, comparison with the reference). Include folder: rapidq_ref/RQInc, built by rapidq_ref/tools/build_standard.py, contents in rapidq_ref/RQInc.md.

1. Why it is needed

An old Rapid-Q program usually cannot be compiled in unIDE without changes. The .bas file names its include files, resources and DLLs, but not the full paths where they were on the author's computer. rc.exe stops at the first missing file («$INCLUDE file X does not exist»), so the program has to be compiled again and again, one file at a time.

Before each build unIDE reads the source itself, finds everything the program needs, and checks whether it is where rc.exe and Windows will look for it. What is missing is shown in one list, searched on disk in one pass and copied to the right folder.

2. What is checked

The main .bas of the project is read together with all include files it includes, nested ones too.

  • $INCLUDE "file" and $INCLUDE <file>: the same way rc.exe looks for them — a full path as is, otherwise the folder of the program (rc.exe runs there) and then the include folder passed with -I. A path inside the name is kept: $INCLUDE "Object\QINI.inc" must be Object\QINI.inc under one of these folders.
  • $RESOURCE Name AS "file": in the same folders. The Rapid-Q documentation says that a resource file in quotes is searched in the current directory and the include paths (chapter 3).
  • DECLARE SUB|FUNCTION ... LIB "x.dll": where Windows looks for a DLL when the exe starts — the folder of the exe, the system folders of Windows and the folders of PATH. A name without an extension gets .dll.

Conditional blocks. $IFDEF, $IFNDEF, $ELSE, $ENDIF, $DEFINE, $UNDEF are followed, also directives renamed with $DEFINE (brem / erem and remb / reme of RAPIDQ.INC are known in advance). A name counts as defined only if its $DEFINE was met earlier in the text. Includes, resources and DECLAREs inside an inactive block are not checked. The debugger reads conditional blocks the same way (Debugger).

Lines continued with _ are joined, so a DECLARE split over several lines is read as one statement. Comments are skipped.

3. When everything is in place

In the compilation log the check is a step of its own, before «--- Компиляция»: the line «--- Препроцессор: <file>.bas», then how many files were read and that nothing is missing, and the build goes on. While the files are read, the progress panel above the editor shows «Препроцессор <file>.bas»; if something is missing, it turns red with the number of missing files before the window opens.

Strict check before rc.exe (FB smart)

The aim is to find what rc.exe accepts but what can make the program work wrong. The check box FB smart in the Project frame, to the right of the list «rc.exe», runs the translation to FreeBASIC (RqToFb, mode FB Smart) before rc.exe, after the preprocessor, without building with fbc. Its log has three kinds of records:

  • Errors of the program that rc.exe lets through: GOTO to a label in another SUB (labels in Rapid-Q are common to the whole program, the jump goes into the middle of another procedure), a method or property of an object that has no DIM or CREATE (with $TypeCheck off such a name is allowed), CASE > 5 instead of CASE IS > 5 (in Rapid-Q it is not a comparison), a block not closed, BIND to a SUB that does not exist, TYPE declared twice.
  • Suspicions: a variable that is not declared and never gets a value (always 0 or "" — usually a misprint), a string put into a numeric variable or a number into a string one, DECLARE without a body (the call does nothing), different parameters in DECLARE and in the header, a second declaration or $DEFINE, TRUE / FALSE without RAPIDQ.INC.
  • Limits of the translation (RETURN with a label, some CALLFUNC, QUICKSORT, INITARRAY ...): for rc.exe this is correct code. They are written to the log as «Info: ограничение перевода в FreeBASIC, для rc.exe не важно» and do not stop the build.

Suspicions in files of the include folders (Include of the project, Include UnIde, Include User) are about libraries rather than the program: they do not open the window, and in the window they are hidden behind the check box «Suspicions in files of the include folders». Errors are shown wherever they are.

If there are no errors of the program and no suspicions in its files, rc.exe builds. Otherwise it depends on the check box Info only to the right:

  • Info only set — everything only goes to the log, rc.exe builds anyway.
  • Info only not set — the window «Строгая проверка» opens: errors first, then suspicions; for the selected one the reason and what can be done. rc.exe is not started, unless «Собрать rc.exe как есть» («Собрать rc.exe» if there are only suspicions) is pressed.

What the window can offer:

  • Find the definition — for an object or a variable without DIM / CREATE and for DECLARE without a body: «Найти определение» looks for DIM / CREATE (or SUB / FUNCTION with a body) in .inc, .bas, .cmp files of the include folders, of the program folder with subfolders and of the folder above; commented ones are marked. A found file is included: the $INCLUDE of it is uncommented if the program has it commented out, otherwise a line $INCLUDE is added after the last include at the top of the program. The whole file is included, with its other declarations.
  • A similar name — a label in the same procedure for GOTO / GOSUB (w8file and w81file:), a declared or assigned variable for an undeclared one (crlfcrlf and crlf), a SUB / FUNCTION for BIND: up to two letters different (one for names up to 4 letters), or one name the beginning of the other. «Заменить на ...» puts it into the line.
  • CASE IS — «Вставить IS» turns CASE > x into CASE IS > x.
  • RAPIDQ.INC — for TRUE / FALSE, if the file is in an include folder.
  • Open the first declaration — for a second declaration.
  • Where the intention cannot be seen from the text (where a block should end, which of two declarations is right, what a string in a number meant) — the reason and «не могу предложить вариант исправления».

The window is not modal: the main window can be used while it is open, and the build waits until it is closed. Changes are made in the editor (they can be undone there) and the file is saved; «Открыть строку» shows the line. What was fixed is checked again at the next build. The check boxes are stored for the main file (editor.ini, section [RapidQ.Strict]); the translated files go to _rqfb next to the program. Only what RqToFb recognises is found: errors of logic (a wrong condition, a wrong order of actions) are not.

4. When something is missing

Each missing file is written to the log with the file and line where it is used. Then the window «Недостающие файлы программы» (missing files of the program) opens. The window is not modal: the main window can be used while it is open, and the build continues when it is closed. Its position and size are kept in editor.ini, section [RqDepsWindow]. From top to bottom:

  • The top field: «Inc файлы не найдены в папках по умолчанию», the paths of Include UnIde and Include User (they can be selected and copied), the folders «Искать» searches: the folder of the program with subfolders, the folder above it and the folders chosen with the button «...», then the button «Искать».
  • The list of missing files: name as written in the source, kind (inc, resource, DLL), where it is used (file and line), the number of copies found, size, creation time and modification time of the copy that will be taken, its path. The creation time of a copied file is the time of copying, so the modification time is shown too. A check box marks what to copy.
  • Copies on disk: shown only when the file selected above has more than one copy. Path, size, creation time and modification time of each copy. The selected copy is the one that will be taken; clicking another row takes that one.
  • Preview: the text of the selected copy, so that it can be read before copying, highlighted with the color scheme of the program (the same .clr and theme the editor uses for it). For DLLs and pictures there is no preview.
  • The lists and the preview are separated by splitters.
  • Below: why this copy was taken and the full path where it will be copied; «Куда» (where); the buttons.

Search

When the window opens, the missing files are looked for in the Include folders only:

  1. Include UnIde — the Include folder that comes with unIDE;
  2. Include User — your own Include folder (RapidQ include settings).

«Искать» looks for what is still missing in the folder of the program with subfolders, in the folder above it and in the folders chosen with the button «...»: it opens the window Directory Tree, and the folders checked in its list are taken (with subfolders, in the order of the list; stored in editor.ini, section [RqDepsSearch]).

A folder already searched in an earlier step is not searched again. Inside each folder, subfolders with «inc» in the name are searched first. During the search the button «Искать» becomes «Стоп» and stops it.

A subfolder from $INCLUDE that does not exist

If the source has $INCLUDE "Object\QStatusBarEx.inc", but the file lies in the Include folder itself and there is no subfolder Object, clicking its row asks what to do: «Исправить путь в исходном файле» (the line becomes $INCLUDE "QStatusBarEx.inc"; it is changed in the editor and the file is saved; only the first place where the file is included) or «Создать подпапку \Object\ в Include UnIde и скопировать туда QStatusBarEx.inc». When the file then lies where rc.exe looks for it (the -I folder or the folder of the program), it leaves the list.

Which copy is taken

  • Include file: the first copy whose text matches the reference (rapidq_ref/incOld, compared as in INC Manager).
  • If none matches and the name in $INCLUDE has a path (Object\QINI.inc): the first copy in a folder with the same path (...\Object\QINI.inc).
  • Otherwise the first copy in the order of the search, with the note «проверьте» (check it).
  • Resources and DLLs: the first copy found; the search for that name stops there, its other copies are not looked for.

Where it is copied

  • Include files and resources: to the -I folder of this build. For each file this can be changed to the folder of the program («Куда»).
  • The path from $INCLUDE is kept: Object\QINI.inc goes to <folder>\Object\QINI.inc, the subfolder is created. Otherwise rc.exe would not find it.
  • A name with a drive (C:\...) is copied to that very path.
  • DLL: by default to the folder of the program — Windows looks for a DLL next to the exe, not in the -I folder. «Куда» can still send it to the -I folder, to keep it with the include files.

Buttons

  • Скопировать — copies the selected copies of the checked files where «Куда» says, without building; the window stays open, copied files are unchecked. What was copied goes to the compilation log when the window closes.
  • Копировать отмеченные и собрать — copies the selected copies of the checked files and starts the build.
  • Собрать без копирования — starts the build as is.
  • Отмена — the build does not start.
  • Не спрашивать про неотмеченные — the unchecked names are no longer checked for this program. They are stored in editor.ini, section [RqDepsIgnore], key — the path of the main .bas. Useful for DLLs that are declared but not used. To check them again, remove the key.

What was copied and from where is written to the compilation log.

Check of include files from Include User

Copies taken from Include User were written for the user's own programs and may contain errors that rc.exe does not accept. After the search they are checked as in INC Manager. If there are errors:

  • an orange panel with the number of errors and two buttons, «Исправить» and «Не исправлять», appears under the list of missing files (under the list of copies, if it is shown);
  • below it is the list of errors: for each file a line with its path and status, then the lines «стр. N: ...». A click on such a line shows that file in the preview and selects line N. Selecting another copy in the list above does not clear the list of errors;
  • «Исправить» corrects the unambiguous errors in the files themselves: directives without $, numbers with U/L suffixes, 0x of C (becomes &H), ; outside a string (becomes a comment). The other errors are corrected by hand. The original file is kept as .bak (or .bak1, .bak2 ... if it exists). The list then shows what was changed and the result of a new check;
  • Undo deletes the corrected files and restores them from .bak;
  • «Проверить и исправить» does the same for the copy that will be taken for the file selected in the list.

5. Include folders: Include UnIde and Include User

IDE Options — Compilers — RapidQ Basic has two fields:

  • Include UnIde — the set that comes with unIDE, rapidq_ref/RQInc (empty field — this folder next to the exe): RQProc.inc (numeric constants and functions), RQControls.inc (components), and next to them checked separate include files — the files of incOld without errors of the INC Manager check under their own names (mostly components: they exist in several versions) and the separate files of inc_sys with _sys in the name (debug_sys.inc, var_sys.inc ...);
  • Include User — the user's own common path to the include files his programs were written with.

In Project Properties the project chooses one folder from a list: Include UnIde (default), Include User, or a folder of its own («...» adds it to the list; «Удалить» and «Удалить все» remove own folders). Below the list both standard paths are shown. The chosen folder is passed to rc.exe with -I; the choice and the list are stored in the project settings. The same choice is in the Project frame of the main window, in the upper line, to the right of the name of the main file: it shows which folder the project uses now (the full path is in the hint and in the opened list) and switches it; the choice is stored in the project. A file without a project always uses Include UnIde. The files of incOld that were not taken into RQInc and the reasons are listed in rapidq_ref/RQInc.md.

A file found by the preprocessor and copied to the -I folder stays there, so the next program that needs it finds it at once.

6. Find inc file

View — Find inc file searches one name on disk by hand. The name may be a mask: * — any characters, ? — one character (QColorDialog*.inc). Order: Include (-I), Include UnIde, Include User (each only if it is another folder), the current folder with subfolders, the folder above, then all local disks (check box) or a chosen folder. Copies appear in the list while the search goes on; each copy is compared with the reference. After «Стоп» the copies already found stay in the list. The window stays above the editor window.

7. Limits

  • A name in $IFDEF counts as defined only after its $DEFINE in the text. A name defined by rc.exe itself or on its command line is unknown, so such a block is taken as inactive.
  • Paths of $INCLUDE are resolved from the folder of the program and the -I folder, not from the folder of the including file — as unIDE assumes rc.exe does.
  • $INCLUDE <file>: rc.exe also looks in «the environment search paths»; these are not checked.
  • The include files nested in a file that is missing are not known until it is copied. They are checked at the next build.
  • Only the build with rc.exe is checked. The FreeBASIC build and the probe build of a form snapshot are not.
  • Whether a DLL is really loaded at start depends on Rapid-Q; the preprocessor only checks that Windows can find it.
