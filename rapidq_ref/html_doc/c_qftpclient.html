QFTPCLIENT Component

Extends QOBJECT · source: inc/QFTPCLIENT.INC, line 139 · author: Jacques Philippe · date: January 2001

An FTP client object based on wininet.dll that connects to a server, manages directories, uploads, downloads, renames and deletes files, and lists files with their size, date and attributes.

QFtpClient extends QObject and wraps the WinINet FTP functions. Connect opens an Internet session (InternetOpenA with Agent, OpenType, ProxyName, ProxyByPass and Open_dwFlags) and connects to the server (InternetConnectA, passive mode for the FTP service). Most methods return the WinINet result (non-zero on success) and put a status text in ErrorMsg that includes the server's last response from ReadMessage.

FindFirstFile and FindNextFile enumerate remote files matching a filter; after each call the properties FileName, DosFileName, FileSize, FileTime, FileTimems, FileDate, FileDateEU, FileDateTime, FileAttributes and FileAttributesAsString describe the current file. The last-write time is converted to local time and formatted as strings. Close closes the find, FTP and Internet handles.

QFTPCLIENT inherits the properties, methods and events of QOBJECT; the tables below list only what the component adds or redefines (public members).

QFtpClient Methods

MethodTypeDescription
ReadMessageFUNCTION AS STRINGReturns the last response text from the server (InternetGetLastResponseInfoA), or an empty string.
ConnectFUNCTION(sRemoteServer as String, sLogin as String, sPassword As String) AS LONGConnect(sRemoteServer, sLogin, sPassword) opens the Internet session and connects to the FTP server; returns the FTP handle, or 0 on failure.
CloseFUNCTION AS LONGCloses the FTP, Internet and find handles and returns the product of the two close results; ErrorMsg reports the outcome.
GetDirFUNCTION AS STRINGReturns the current remote directory, or an empty string on error.
MakeDirFUNCTION(sNewDirectory As String) AS LONGMakeDir(sNewDirectory) creates a remote directory; returns non-zero on success.
SetDirFUNCTION(sNewDirectory As String) AS LONGSetDir(sNewDirectory) changes the current remote directory; returns non-zero on success.
RemoveDirFUNCTION(sDelDirectory As String) AS LONGRemoveDir(sDelDirectory) removes a remote directory; returns non-zero on success.
PutFileFUNCTION(sLocalFileName As String, sRemoteFileName As String) AS LONGPutFile(sLocalFileName, sRemoteFileName) uploads a local file using FtpTransferType; if the remote name is empty the local name is used. Returns non-zero on success.
GetFileFUNCTION(sRemoteFileName As String, sLocalFileName As String, iflagOverwrite As Long) AS LONGGetFile(sRemoteFileName, sLocalFileName, iflagOverwrite) downloads a file; when iflagOverwrite is non-zero an existing local file is overwritten, otherwise the download fails if it exists.
RenameFUNCTION(sOldName as String, sNewName as String) AS LONGRename(sOldName, sNewName) renames or moves a remote file (no overwrite); returns non-zero on success.
DeleteFUNCTION(sRemoteFileName As String) AS LONGDelete(sRemoteFileName) deletes a remote file; returns non-zero on success.
FindFirstFileFUNCTION(sfilter As String) AS STRINGFindFirstFile(sFilter) starts a search of the current remote directory and returns the first matching file name (empty if none), filling the File* properties.
FindNextFileFUNCTION AS STRINGReturns the next matching file name and fills the File* properties; returns an empty string and closes the search handle when there are no more files.

Notes

  • A comment in GetFile says FtpGetFileA "always returns ZERO ????", so its return value and ErrorMsg may not reflect the real result.
  • Delete is marked "(dont work)" in the source.
  • Close returns ftpHandle * hOpen with the comment "???? must equal 1 ????"; after Close, ftpHandle holds the InternetCloseHandle result (1 on success) instead of 0.
  • FindNextFile closes hFind when the list ends but does not reset it to 0, so a later Close calls InternetCloseHandle on the already closed handle.
  • FileDateTime is taken from the raw UTC FILETIME, while FileDate and FileTime use local time.
  • The constant QFTP_PassiveConnection is declared but not used; the FILETIME fields are flattened into separate longs because of a RapidQ bug with nested types, as the source notes.

QFtpClient Examples

Example written for this page from the members above; not run.

DIM Ftp AS QFtpClient
DIM f AS STRING
IF Ftp.Connect("ftp.example.com", "anonymous", "me@example.com") THEN
  Ftp.FtpTransferType = QFTP_TRANSFER_TYPE_BINARY
  Ftp.SetDir("/pub")
  f = Ftp.FindFirstFile("*.*")
  WHILE f <> ""
    PRINT f; " "; Ftp.FileSize; " "; Ftp.FileDate
    f = Ftp.FindNextFile
  WEND
  Ftp.GetFile("readme.txt", "readme.txt", 1)
  Ftp.Close
ELSE
  ShowMessage Ftp.ErrorMsg
END IF
