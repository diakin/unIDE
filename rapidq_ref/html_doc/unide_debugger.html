How the unIDE debugger works

Code: RqDbgInstr.pas (the instrumented copy and the code inserted into it) and the RqDbg... methods of Unit1.pas (build, session, editor, Watch). Test programs: tests/RqDbg. Applies to programs built with rc.exe; with the FreeBASIC build (RqToFb) the debugger does not work.

1. Why an instrumented copy

A Rapid-Q exe is the interpreter with the program appended as byte code. A breakpoint at a machine-code address would stop inside the interpreter, and there is no table that maps an address to a line of Basic. A native debugger (Win32 debug API, as unIDE uses for Delphi programs) therefore cannot stop on a Basic line.

Instead, unIDE writes a copy of the program, <name>_rqdbg.bas, next to the main .bas. Before each statement the copy has a check with the number of that place (a point). The copy is compiled by rc.exe into the usual <name>.exe. unIDE keeps the table «point → file, line»; the program itself only knows the numbers.

The copy is built when the program is started with a breakpoint set in its main .bas or in one of its $INCLUDE files, or with F7, F8 or F4. Without them the program is built and run as usual.

2. What is inserted

For this program

$APPTYPE CONSOLE
DIM Total AS LONG
SUB AddUp (Count AS LONG)
  DIM LoopIdx AS LONG
  FOR LoopIdx = 1 TO Count
    Total = Total + LoopIdx
  NEXT
END SUB
Total = 0
AddUp 10
PRINT Total

the copy looks like this (the debugger runtime after the first directives is left out; Watch has the expression Total * 2):

DIM Total AS LONG
SUB AddUp (Count AS LONG)
  DIM RqDbgLvl AS LONG
  RqDbgDepth = RqDbgDepth + 1
  RqDbgLvl = RqDbgDepth
  DIM LoopIdx AS LONG
  IF RqDbgBrk(1) THEN
    RqDbg(1, RqDbgLvl, 5, 0)
    IF RqDbgWant THEN GOSUB RqDbgVars0
  END IF
  FOR LoopIdx = 1 TO Count
    IF RqDbgBrk(2) THEN
      RqDbg(2, RqDbgLvl, 6, 0)
      IF RqDbgWant THEN GOSUB RqDbgVars0
    END IF
    Total = Total + LoopIdx
  NEXT
  RqDbgDepth = RqDbgLvl - 1
  EXIT SUB
RqDbgVars0:
  RqDbgVal("p", "Count", "LONG", STR$(Count))
  RqDbgVal("l", "LoopIdx", "LONG", STR$(LoopIdx))
  RqDbgHalt
  RETURN
END SUB
IF RqDbgBrk(3) THEN RqDbg(3, 0, 9, 1)
Total = 0
IF RqDbgBrk(4) THEN RqDbg(4, 0, 10, 1)
AddUp 10
IF RqDbgBrk(5) THEN RqDbg(5, 0, 11, 1)
PRINT Total
' --- unIDE: global variables for the debugger ---
SUB RqDbgGlobals
  RqDbgVal("g", "Total", "LONG", STR$(Total))
  RqDbgWV = Total * 2
  RqDbgWT = RqDbgWS + RqDbgWV
  RqDbgVal("w", "0", "", RqDbgWT)
END SUB
  • The check. RqDbgBrk(N) is an array of flags, one per point. While the flag is 0 the check costs one comparison; test RqDbgT3_Speed.bas gave a slowdown of about 1.7 times against the program without checks. The parameters of RqDbg: point number, call level, line key (the source line, for the «same line» rule), and 1 if the place has no dump block (main part, SUBI/FUNCTIONI).
  • Call level. At the start of each SUB/FUNCTION the local RqDbgLvl gets depth + 1; before END SUB and EXIT SUB the depth goes back. The level is what Step over needs. An EXIT SUB inside a one-line IF is not changed (an insertion there would change the line); the next point of the calling SUB corrects the depth.
  • Names. The inserted code uses names starting with RqDbg. If the program already contains a word with this beginning anywhere, even in a comment, another prefix is taken (UniDbg, UnideDbg, ...), otherwise rc.exe reports «identifier already in use».
  • Line map. Every line of the copy remembers its source file and line, so rc.exe errors in the copy are shown at the line of the original file. The messages of a session are saved to <name>_rqdbg.log.

3. Stopping and going on

The program and unIDE communicate through two files next to the main .bas and two named Windows events:

ObjectWritten byContents
<name>_rqdbg.cmdunIDEThe command: m mode (0 Run, 1 Trace into, 2 Step over, 3 Run to cursor), r point (Run to cursor), b point for each breakpoint, c point for a conditional breakpoint, k N for an enabled Watch condition, #end.
<name>_rqdbg.statethe programWhere it stopped: s point level, then one line per value kind name|type=value (kind: p parameter, l local, g global, w Watch expression), #end. Long values are cut at 300 characters, CR is written as CHR$(182).
event «stop»the programSet when the state file is written and closed.
event «go»unIDESet when the command file is written.

The event names are new for each build (unIDE_RqDbg_<process>_<tick>_S and _G), so a program left from an earlier build cannot set them. unIDE creates both events before it starts the exe; the program opens them by name with CreateEventA (declared in the copy through DECLARE ... LIB "kernel32").

The order of a stop:

  1. The flag of the point is set, the program calls RqDbg. RqDbg decides whether to stop here (see the modes below). If not, it returns at once.
  2. If it stops, it opens the state file and writes s point level. In a SUB it then raises RqDbgWant, and the check jumps with GOSUB to the dump block of this SUB, which writes the parameters and locals. In the main part and in SUBI it goes on directly.
  3. RqDbgHalt writes the globals and the Watch expressions (RqDbgGlobals), #end, closes the file, sets «stop» and waits for «go» with WaitForSingleObject(..., -1).
  4. While it waits, the whole thread of the program stands still: its windows are not repainted and its timers and events do not run, as with a Delphi program stopped in a debugger. There is no DOEVENTS in the wait. This was checked with RqDbgT2_Target.bas / RqDbgT2_Control.bas.
  5. unIDE does not wait: a timer checks the «stop» event with zero timeout. When it is set, unIDE reads the state file, shows the line in its own editor, fills Locals and Watch and the value hint under the mouse.
  6. On F9, F7, F8 or F4 unIDE writes the command file and sets «go». The program reads the command (RqDbgReadCmd), sets the flags for the new mode and continues.

The command file is read only at a stop (and once at start). A breakpoint set or removed while the program runs takes effect after the next stop. If the program stops on a breakpoint that has been removed in the meantime, unIDE lets it go on at once with the same command.

4. Modes

ModeFlags setWhere RqDbg stops
Run (F9)breakpointsat a breakpoint (a conditional one only when its condition holds)
Trace into (F7)all pointsat the next point, also inside a called SUB; not again on the same line of the same level (FOR ... : ... : NEXT on one line)
Step over (F8)all pointsat the next point of the same level or higher; deeper points stop only if they are breakpoints
Run to cursor (F4)breakpoints and the point of the cursor lineat the cursor line or at a breakpoint met before it

While a stop is being handled (dump, Watch expressions that call a FUNCTION of the program), RqDbgBusy is set and all checks return at once, so the debugger does not stop inside its own work.

5. Values of variables

Rapid-Q has no reflection: a value can be read only by code compiled into the program. So the copy contains the reading code for every variable that can be shown:

  • Parameters and locals of a SUB/FUNCTION — in a dump block at the end of this SUB, after all its DIM, with the label RqDbgVars<N>. It is reached with GOSUB from the check and only when the program stops, so the check itself stays short. Test RqDbgT1_Gosub.bas showed that GOSUB to a label inside a SUB works and the parameters and locals are visible there; labels are common to the whole program, so each block gets its own number.
  • Globals — in SUB RqDbgGlobals at the end of the copy, after all declarations. Because both blocks stand after the declarations, there is no reference to a variable before its DIM.
  • Shown are declared variables of simple types: DIM ... AS STRING, BYTE, WORD, DWORD, SHORT, INTEGER, LONG, SINGLE, DOUBLE, names with suffixes, DEFINT and the like, and parameters. Not shown: arrays, objects, VARIANT, own TYPEs, variables used without DIM, globals of $INCLUDE files that are not inserted into the copy.

6. Watch expressions

Rapid-Q cannot evaluate a text at run time, so the expressions in the Watch window at the moment of the build (a(3), Form.Caption, LimitVal + TotalVal) are compiled into the copy:

  • into the dump block of a SUB where all names of the expression are known and at least one of them is a parameter or local of this SUB;
  • otherwise into RqDbgGlobals, if all names are global (DIM, CREATE, CONST, SUB and FUNCTION of the main file and inserted $INCLUDE files).

Built-in functions (LEN, MID$, ...) and properties after a dot do not count as names. An element of an array or a variable of a known simple type is written through STR$ or as is; anything else through VARIANT: RqDbgWV = expression, RqDbgWT = RqDbgWS + RqDbgWV, where RqDbgWS is a VARIANT holding "" (string + number gives a string). An expression with : or ' outside quotes is not inserted. A new expression is evaluated only after the next build; the log of the build says for every expression where it is evaluated or why it is not.

7. Conditions

  • Conditional breakpoint. The condition (a Rapid-Q expression) is written into the copy before the call of RqDbg at the first point of the line and evaluated there, in the scope of that line. unIDE enables it with c point; the point stops only if the condition holds. b point enables the point without the condition. F7 and F8 do not look at conditions.
  • Condition of a Watch line (expression LoopIdx, condition =10). It applies to every breakpoint where the expression is evaluated: a breakpoint stops only if all such conditions hold. The conditions are checked in the dump block of the SUB (or in SUB RqDbgWatchCond for global names) before the state file is opened; if one fails, the program goes on. unIDE enables a condition with k N.
  • A condition added or changed during a session works after the next build; removing it works at once.

8. Where no check is inserted

  • CREATE ... END CREATE and TYPE ... END TYPE (taken as a whole), DECLARE, DIM, CONST, DEF..., $ directives, comments;
  • ELSE, ELSEIF, CASE, LOOP, NEXT, WEND, END IF / SELECT / WITH, SUB headers and ends, the place between SELECT CASE and the first CASE;
  • a one-line IF (something after THEN) is one statement together with the rest of the line;
  • lines continued with _ are joined first;
  • conditional compilation: $IFDEF, $IFNDEF, $ELSE, $ENDIF and their aliases through $DEFINE (brem/erem and remb/reme of RAPIDQ.INC). A name counts as defined only if its $DEFINE is in the file; a block of $IFDEF of an unknown name is copied as is, without checks.

9. $INCLUDE files

An $INCLUDE file is inserted into the copy as text in place of its $INCLUDE line, and instrumented with the main file, if it has a breakpoint, is open on a tab marked with this main .bas, is the file of F4, or lies on the include path to one of these. The inserted text is framed by two comments starting with ' unIDE: (the $INCLUDE line and the end of the file); a repeated $INCLUDE of an inserted file becomes a comment. Other $INCLUDE lines stay as they are: rc.exe takes the original file, without checks, and F7 does not enter its SUBs.

10. Limits

  • No Pause: a running program can be stopped only at a point whose flag is set.
  • One session at a time.
  • Breakpoints set while the program runs work after the next stop; new Watch expressions and conditions after the next build.
  • Breakpoints, conditions and the Watch list are not saved between runs of unIDE.
  • If unIDE is closed and the program reaches a point, it waits for «go» for ever.
  • A Watch condition with local names in a SUBI is not checked (a SUBI has no dump block).
  • Not available with the FreeBASIC build of a Rapid-Q program.

11. What was checked

With rc.exe on the user's computer (tests in tests/RqDbg, see README.txt there): GOSUB to a label in a SUB with parameters and locals visible (test 1); stopping on WaitForSingleObject and continuing from another process, the program blocked while it stands (test 2); the cost of the checks (test 3); breakpoints, F7, F8, F4, F9, values of variables and Watch expressions through VARIANT (test 4, confirmed 2026-10-05). Conditional breakpoints, Watch conditions, $INCLUDE files under the debugger and the session log were built and checked with FPC only and are not yet confirmed with rc.exe. Not checked: RETURN inside a block IF (used in the dump block with Watch conditions).
