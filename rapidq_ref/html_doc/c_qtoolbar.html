QTOOLBAR Component

Extends QOBJECT · source: inc/QToolBar.inc, line 27 · author: Nastase Eodor · version: 1.2 (stable)

A toolbar component that wraps the Windows common-controls toolbar (ToolBarWindow32) with image lists, check and drop-down buttons, tooltips and a context menu.

QToolBar registers its own window class "QToolBar" as a subclass of the common-controls class ToolBarWindow32 and creates the window with CreateWindowEx when you assign Parent (a QForm) or Parent2 (a QPanel). It also subclasses the parent window procedure so it can handle WM_COMMAND (button clicks) and WM_NOTIFY (tooltip text and drop-down arrows).

Buttons are added with AddButton, InsButton and AddSeparator; the style can be tbsButton, tbsCheck, tbsCheckGroup or tbsDropDown. Each button's TBBUTTON structure and extra data (down, enabled, visible, hint, show hint, drop-down menu) are kept in memory blocks allocated with the Memory.inc helpers, so RecreateWnd can rebuild the toolbar when style properties change. Buttons are addressed by a 0-based index.

Clicks fire OnButtonClick with the button index. A right click shows PopupMenu, and drop-down buttons show the QPopupMenu set with SetButtonDropDown; WM_COMMAND messages sent to the toolbar window, such as those from these menus, fire OnCommand.

QTOOLBAR inherits the properties, methods and events of QOBJECT; the tables below list only what the component adds or redefines (public members).

Requires

  • Memory.inc ($INCLUDE, unless __RQMEMORY is already defined): NewPtr, NewZStr, StrFromPtr, PtrFree, MemCpy
  • Windows API declarations, structures and constants that this file does not declare, such as CreateWindowEx, SendMessage, SetWindowLong, CallWindowProc, InitCommonControls, TBBUTTON, NMHDR, TOOLTIPTEXT, TBNOTIFY, LOGFONT and the TBSTYLE_*/TB_*/TBN_* constants
  • SetNewCallBack_4, used by Register to create callback addresses (defined for example in rapidq2.inc)

QToolBar Events

EventTypeOccurs when...
OnButtonClickSUB(ButtonIndex&)Event OnButtonClick(ButtonIndex&) fired when a button is clicked, with its 0-based index. For check buttons the stored down state is updated first.
OnCommandSUB(NotifyCode&,CommandID&,hwndCtrl&)Event OnCommand(NotifyCode&, CommandID&, hwndCtrl&) fired when the toolbar window receives WM_COMMAND, for example from the context or drop-down menus it displays.

Notes

  • AddButton, InsButton and AddSeparator store a button only if TB_ADDBUTTONS/TB_INSERTBUTTON succeeds, so Parent (or Parent2) must be assigned before buttons are added.
  • Images is attached only when the window is created (CreateWnd); Refresh re-attaches only HotImages and DisabledImages.
  • DelButton checks Index& < ButtonCount - 1, so the last button can never be deleted.
  • SetButtonVisible passes Visible& directly as the TB_HIDEBUTTON hide flag, so a non-zero value hides the button; GetButtonVisible likewise returns the hidden state when the window exists.
  • SetButtonDown, SetButtonEnabled and SetButtonVisible send messages to Handle without checking that the window exists.
  • SetButtonHint allocates a new string each time without freeing the previous one.
  • SetButtonCaption does nothing for a button that was added without a caption.

QToolBar Examples

Example written for this page from the members above; not run.

$INCLUDE "QToolBar.inc"

SUB ToolClick(ButtonIndex&)
  ShowMessage "Button " + STR$(ButtonIndex&)
END SUB

CREATE Form AS QFORM
  Caption = "QToolBar demo"
  Width = 400
END CREATE

DIM Tool AS QToolBar
Tool.Parent = Form
Tool.AddButton(0, "New", tbsButton)
Tool.AddButton(1, "Open", tbsButton)
Tool.AddSeparator
Tool.AddButton(2, "Bold", tbsCheck)
Tool.OnButtonClick = ToolClick
Form.ShowModal
