QDIR Component

Extends QOBJECT · source: inc/QDir.Inc, line 143 · author: Jacques Philippe · version: 1.0.4 · date: April 2004

Non-visual file finder that scans a directory, or a directory tree, for files matching a filter and attribute rules, and fires an event for each file found.

QDir searches with the kernel32 functions FindFirstFileA and FindNextFileA. Dir scans one directory and Dirs scans it and all its subdirectories. For every entry that passes the attribute filter it fills its properties (names, path, size, attributes, and creation, last access and last write times converted to local time) and calls OnFileFound. The date/time properties at the top level (Date, Time, DateEU and so on) are copied from the last write time.

Attributes are given as letters: A archive, D directory, H hidden, N normal, R read-only, S system, T temporary, C compressed, and 0 for no attribute. An entry is rejected when it has any attribute listed in RejectedAttributes, and it must have every attribute listed in MustAttributes. While a search runs, a small black window (frmDirStop) is shown; clicking it sets FlagStop and aborts the scan. DoEvents is called in the scanning loops.

Two extra functions change file times (SetFileTime) and attributes (SetFileAttributesA).

QDIR inherits the properties, methods and events of QOBJECT; the tables below list only what the component adds or redefines (public members).

QDir Methods

MethodTypeDescription
DirSUB(sPathFilter As String, sRejectedAttributes As String, sMustAttributes As string)Dir(PathFilter, RejectedAttributes, MustAttributes): scans one directory for entries matching PathFilter (for example "C:/temp/*.bas"; "/" is accepted as separator) and calls OnFileFound for each one that passes the attribute rules.
DirsSUB(sPathFilter As String, sRejectedAttributes As String, sMustAttributes As String)Dirs(PathFilter, RejectedAttributes, MustAttributes): like Dir, but also scans all subdirectories of the starting directory.
ChangeFileDateAndTimeFUNCTIONI(...) AS LONGChangeFileDateAndTime(PathFileName$, [WhichTimes$], year, month, day, hour, minute, second): sets file times; WhichTimes may contain "CRE", "ACC" and "WRI" (empty means last write time only). Returns 1 on success; on error it shows a message and returns 0.
ChangeFileAttributesFUNCTION(sPathFileName As string, attributesAsString As String) AS LONGChangeFileAttributes(PathFileName, AttributesAsString): sets the file attributes from letters "ADHNRSTC" and returns the result of SetFileAttributesA (non-zero on success).

Notes

  • Only one search per QDir can run at a time; a second call shows "QDIR ERROR : QDIR ALREADY SEARCHING".
  • A filter that matches nothing, or a directory that does not exist, gives no error; the error messages are commented out.
  • ChangeFileDateAndTime treats a CreateFile result of 0 as failure, but CreateFile returns -1 on failure, so a missing file is not detected at that point.
  • ChangeFileDateAndTime passes the given time to SystemTimeToFileTime without converting from local time, while the times read by Dir and Dirs are converted to local time. It always sets the milliseconds to 333.
  • Dir: for a relative filter, Path gets the application path in front, but FindFirstFile is called with the filter as given. Dirs searches with Path & "*.*" and Path & Filter, which already include the application path.
  • In Dirs, FlagStop is checked only after all files of the current directory have been processed.
  • The source notes RapidQ bugs with nested types, so the FILETIME fields of WIN32_FIND_DATA are written out as separate LONGs.

QDir Examples

Example written for this page from the members above; not run.

$INCLUDE "QDir.Inc"
CREATE Form AS QFORM
  Width = 500
  Height = 300
  CREATE List AS QLISTBOX
    Align = 5
  END CREATE
END CREATE
DIM D AS QDir
SUB FileFound
  List.AddItems D.PathFileName & "  " & STR$(D.Size) & "  " & D.DateEU
END SUB
D.OnFileFound = FileFound
D.WithDotsDirs = 0
D.Dirs("C:/Projects/*.bas", "H", "")
Form.ShowModal
