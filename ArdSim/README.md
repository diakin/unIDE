# ArdSim — запуск скетча Arduino на PC

Скетч `.ino` компилируется MinGW g++ как обычная программа Windows. Вместо железа подключаются заглушки из `include/` и `src/`:

| Что в скетче | Что в ArdSim |
|---|---|
| `UTFT` (экран 480×320) | буфер RGB565, показывается в окне (×2, если хватает места на экране) |
| клавиатура 5×4 (строки на пинах 13..9, столбцы на 5..8, прерывания FALLING) | кнопки справа от экрана и клавиши PC; матрица эмулируется по `pinMode`/`digitalWrite`, нажатие вызывает прерывание столбца |
| `DueTimer` | таймеры по `QueryPerformanceCounter`, ISR вызывается в безопасной точке |
| `SD` | папка `sim_sd` рядом с exe; имена только 8.3, как на карте |
| `Serial` | поле под экраном |
| `analogRead` | генератор сигналов: гармоники оборотной частоты с фазой от метки, посторонние частоты, шум (см. «Сигналы») |
| тахометр | импульс на пине 3 раз за оборот, спад = метка; копия на A4 |
| `millis`, `micros`, `delay` | реальное время |

Прерывания (пины и таймеры) доставляются в `simPoll()`. Её вызывает каждая функция Arduino API, UTFT и сравнение `String`, поэтому циклы вида `do {} while (btnName == "---");` работают. Если скетч считает долго без вызовов API (например, БПФ), прерывания ждут конца расчёта.

## Сборка

Нужен MinGW-w64: в unIDE пункт меню Arduino → Install MinGW-w64 GCC 12. На Win7 также нужен Universal C Runtime (KB2999226): xPack GCC 12 линкует программы с UCRT.

```
ArdSim\build_sim.cmd D:\путь\к\скетчу\BS10-2024virtkbdSD-sb2.ino
```

Вторым аргументом можно указать папку `bin` с `g++.exe`. Иначе g++ ищется так: `%ARDSIM_MINGW%`, `..\Output\tools\mingw\bin`, `..\tools\mingw\bin`, `%LOCALAPPDATA%\unIDE\tools\mingw\bin`, затем `PATH`.

Результат: `<папка скетча>\ardsim_build\<скетч>_sim.exe`. Если перед запуском задать `set ARDSIM_RUN=1`, exe запустится после сборки.

### Шрифты

UTFT-шрифты (`SmallFont`, `BigFont`, `UbuntuBold` и т. д.) берутся:
1. из `*.c` в папке скетча;
2. из папки `%ARDSIM_FONTS%` (все `*.c`);
3. при сборке из unIDE — из папок libraries со всеми вложенными папками: скетчбук, своя папка библиотек, Arduino IDE (как в Include Library). unIDE берёт имена из объявлений `extern uint8_t Имя[];` скетча и для каждого ищет первый `.c` с массивом-шрифтом этого имени. Найденные файлы — в `ardsim_build\ardsim_fonts.txt`, в журнале сборки — строки «ArdSim: шрифт Имя - файл». Файл, в котором есть массив, уже взятый из другого файла, пропускается, чтобы не было повторного определения;
4. без этого списка (сборка из командной строки) и без `%ARDSIM_FONTS%` — `Documents\Arduino\libraries\UTFT\DefaultFonts.c`.

Шрифт, который не нашёлся, берётся из `ArdSim\fonts` — это замена с тем же размером символа, но другим начертанием. Замены сгенерированы `tools/make_fonts.py`.

Если один и тот же шрифт найден в двух местах, линкер выдаст ошибку о повторном определении. Тогда уберите лишний файл или задайте `ARDSIM_FONTS` на одну папку.

## Сигналы

Настройки лежат в `ardsim.ini` рядом с exe. Файл создаётся при первом запуске и перечитывается на ходу, когда меняется (например, после сохранения в редакторе). Панель в окне меняет обороты, включает тахометр и задаёт 1-ю гармонику A0/A1. Кнопка Apply или Enter в поле записывают значения в тот же ini.

```ini
[Tacho]
Enabled=1      ; 0 - метки нет (ротор крутится, датчика нет)
RPM=1500
Pin=3          ; цифровой пин метки, прерывание по спаду
PulseDeg=10    ; длина импульса в градусах поворота
Analog=4       ; аналоговый канал с копией импульса (A4), -1 - нет
[ADC]
Vref=3.3       ; вольты, соответствующие полной шкале АЦП
[A0]
Offset=1.65    ; постоянная составляющая, В
Noise=0.003    ; шум, В (СКО)
H1=0.3,45      ; гармоника k: амплитуда В, фаза в градусах
H2=0.05,0      ; H1..H10
Freq1=50,0.02,0 ; посторонняя частота: Гц, амплитуда В, фаза; Freq1..Freq4
[A1]
...
```

Сигнал канала: `Offset + Σ Hk.amp·cos(k·угол − Hk.phase) + Σ Freq + шум`, где угол поворота равен 0 в момент метки. Фаза P значит, что максимум гармоники приходится на P градусов поворота после метки. На экране виброметра sb2 при `H1=0.3,45` для A0 и `H1=0.2,120` для A1 показывает F1=44°, F2=119°. Значения АЦП ограничены 0..Vref, разрядность берётся из `analogReadResolution`.

## Ротор (проверка балансировки)

Секция `[Rotor]` превращает 1-ю гармонику датчиков в отклик модели ротора. Грузы ставятся в панели окна, это «установка груза на станке». Прибор ведёт балансировку как обычно.

```ini
[Rotor]
Enabled=1
Angles=with        ; углы грузов по вращению (как показывает прибор); against - против
Sensor1=0          ; датчик 1 = A0, датчик 2 = A1
Sensor2=1
Unbalance1=20,60   ; начальный дисбаланс плоскости 1: г (на радиусе пробного груза), град
Unbalance2=12,200
K11=0.01,30        ; влияние плоскости 1 на датчик 1: В/г, запаздывание в град
K12=0.004,80       ; Ksp: датчик s, плоскость p
K21=0.003,110
K22=0.009,20
Weights1=10@0      ; грузы на роторе, плоскость 1: г@град; г@град ...
Weights2=
```

Отклик датчика s: `V_s = Σ_p K_sp · (дисбаланс_p + грузы_p)`, все величины комплексные. Пробный груз ставится на 0°. При `Angles=with` корректирующий груз вводится с тем углом, который показывает прибор: в окне прибора угол отсчитывается от пробного груза. Строки `H1` датчиков в `[A0]/[A1]` при включённой модели рассчитываются и вручную не задаются.

Точный ответ при этих значениях известен заранее: в каждой плоскости нужен груз, противоположный начальному дисбалансу. Для 2 плоскостей это 20 г @ 240° и 12 г @ 20°.

Проверено на sb2 под wine:
- **1 плоскость** (пробный груз 10 г): прибор выдал 20 г @ 255°, точный ответ модели 20.6 г @ 253.5°. После установки 1x на A0 упала с 11.5 до 0.4 мм/с.
- **2 плоскости** (пробные грузы по 10 г): прибор выдал 20.1 г @ 240° и 12.0 г @ 20°. После установки 1x упала с 11.0/4.5 до 0.0/0.0 мм/с. На A0 остались 2.7 мм/с 2-й гармоники `H2`: от грузов она не зависит.

## Время экрана и клавиатура

- Каждый пиксель UTFT занимает `[LCD] PixelNs` наносекунд (по умолчанию 400), и скетч ждёт это время. Если экран рисуется мгновенно, код клавиши, который таймер клавиатуры держит 50 мс, ещё не сброшен, когда следующий экран начинает ждать клавишу. Тогда меню «проскакивает»: например, «1» в главном меню сразу открывает 1-плоскостную балансировку. При 150 нс так и было. Значение 400 подобрано, а не измерено. Его можно измерить на приборе через `micros()` до и после `myGLCD.clrScr()` (153600 пикселей).
- Нажатие кнопки — один короткий клик. Клавиша отпускается, как только скетч один раз её опросил (строка переведена во вход и обратно в выход). Иначе удержание дольше 50 мс давало бы повтор.

## Окно

- Кнопки клавиатуры BS10. Клавиши PC: `0`–`9`, `F1`, `F2`, `#`, `*`, стрелки (`^ v < >`), `Enter` (Ent), `Esc`. Нажатие держится 120 мс, чтобы его увидел опрос `kbdcheck2` с периодом 50 мс.
- Под клавиатурой при наведении мыши на экран показываются координаты и цвет пикселя (RGB565).
- Поле под экраном — вывод `Serial`.

## Окно Emulator в unIDE

Меню Arduino → **Emulator (ArdSim)** открывает отдельное окно эмулятора (`ArdSimHost.pas`). При первом открытии окно встаёт у правого края unIDE на всю его высоту, поверх панели Git; дальше остаётся там, где его оставили. Пока окно стоит над правой частью unIDE, правая панель растягивается до его левого края, так что редактор кончается там, где начинается эмулятор; после перемещения окна это пересчитывается. Закрытие окна останавливает эмулятор и возвращает прежнюю ширину панели. Кнопки эмулятора стоят в ряду Project (режим Arduino) после Verify, Upload и Program reset, значками:

- **собрать и запустить** (шестерёнка с ключом) — `build_sim.cmd` для скетча (цель сборки Arduino) со своим MinGW unIDE, вывод в Compilation log; окно эмулятора открывается сразу, скетч запускается после успешной сборки;
- **запустить** (прибор с клавиатурой) — запуск уже собранного exe;
- **остановить** (красный квадрат) — остановка эмулятора или сборки;
- **ardsim.ini** (карандаш) — открыть его в редакторе unIDE; после сохранения эмулятор перечитывает его сам;
- **окно ArdSim** — запустить тот же exe отдельным окном ArdSim (с панелью сигналов).

Окно рисует прибор BS10: экран 480×320 точка в точку в узкой зелёной рамке корпуса, под ним панель клавиатуры (цвета и раскладка по фото прибора), ниже вывод Serial. Клавиатура уменьшается, чтобы прибор влез по высоте панели (клавиши не ниже 20 точек). Клавиши прибора нажимаются мышью или клавишами ПК, когда прибор в фокусе (щелчок по нему).

Под прибором панель **Сигналы** (её можно скрыть). На ней тахометр и обороты, 1-я гармоника A0 и A1 (амплитуда и фаза), включение модели ротора и грузы двух плоскостей. «Применить» записывает эти ключи в `ardsim.ini`, эмулятор перечитывает файл за полсекунды. При включённой модели ротора 1-ю гармонику считает эмулятор, поля амплитуды и фазы закрыты. Остальные настройки правятся в самом файле (кнопка ardsim.ini); после сохранения поля панели перечитываются. Пока эмулятор ни разу не запускался, файла нет и панель ничего не пишет: неполный файл эмулятор прочитал бы с нулями вместо умолчаний.

Exe при этом работает в режиме `/host:<имя>` без своего окна ArdSim. Экран, Serial и клавиши передаются через общую память `Local\ArdSim_<имя>`, её создаёт unIDE. Раскладка описана в начале `src/sim_host.cpp` и `ArdSimHost.pas`. Эмулятор завершается сам, если закрылся unIDE.

## Отладка: точки останова, шаги, Watch

`ardprep` вставляет в каждую функцию скетча отладочные вызовы (`include/ardsim_debug.h`):

- `SIM_STEP(файл, строка)` перед каждым оператором. Пустое тело цикла (`while (x);`, `do {} while (x);`) тоже получает такой вызов, чтобы паузу можно было поставить и в ожидании клавиши;
- `SimFrame` в начале функции: из них собирается стек вызовов;
- регистрацию переменных для Watch. Это глобальные переменные, локальные переменные, параметры функций и переменная цикла `for`. Показываются числа, `bool`, `char`, указатели, `String` и массивы этих типов. Объекты других классов (`UTFT`, `File`) не показываются.

Вставки идут в той же строке, что и оператор, поэтому номера строк в ошибках компилятора не меняются. Если `ardprep` не разобрал функцию, он оставляет её без вставок и пишет об этом при сборке. В функции с `goto` локальные переменные блока, где стоит метка, не регистрируются: иначе `goto` перепрыгивал бы конструктор и сборка не проходила. Сборка без вставок: `ardprep -plain`.

Отладка работает в окне Emulator unIDE, когда активна вкладка скетча:

- **F5** в редакторе — точка останова. Точку можно ставить и снимать на ходу;
- **F7** — шаг с заходом в функции. **F8** — шаг без захода. **Shift+F8** — до выхода из функции. **F4** — до строки с кареткой. **F9** — дальше. **Ctrl+F2** — остановить эмулятор;
- пока скетч идёт, F7 и F8 ставят его на паузу на ближайшем операторе. Если эмулятор не запущен, F7, F8 и F4 собирают скетч и запускают его с остановкой на первом операторе (F4 — на строке);
- строка остановки подсвечивается в редакторе, как у отладчика Delphi. Подсказка над именем показывает значение переменной;
- в окне **Watch** выражения вида `имя` или `имя[индекс]` (индекс — число или переменная). Пока окно Watch открыто, значения обновляются раз в полсекунды и на ходу. Пункт меню окна «Добавить переменные процедуры» добавляет локальные переменные функции остановки.

Прерывания (`attachInterrupt`, DueTimer) вызываются эмулятором внутри вызовов Arduino API. Шаги и пауза их пропускают, точка останова в обработчике срабатывает. После остановки в обработчике шаги идут и внутри обработчиков. Пока скетч стоит, часы `millis()`/`micros()` тоже стоят, поэтому после продолжения таймеры не догоняют пропущенное время.

Обмен с unIDE идёт через область отладчика в общей памяти: команды, точки, выражения Watch и ответ эмулятора. Раскладка описана в `src/sim_internal.h` (`SimDbg*`). Exe, собранный прежней версией ArdSim, сразу завершается с кодом 4, и unIDE пишет, что скетч нужно собрать заново.

## Клик по надписи на экране → строка .ino

Если в окне Emulator в unIDE щёлкнуть по надписи на экране прибора, редактор откроет `.ino` на строке, которая эту надпись нарисовала. Нужен скетч, собранный с отладочными вставками, то есть обычной сборкой эмулятора.

- Эмулятор запоминает каждый `print()` из UTFT: прямоугольник текста, сам текст и стек строк. В стек входит рисующий оператор и строки вызовов, которые к нему привели, всего до 6 уровней. Надпись забывается, когда её целиком закрывает `fillRect`, `fillRoundRect`, `clrScr` или `fillScr` либо поверх неё печатается другой текст.
- unIDE выбирает в стеке первую строку, в которой есть строковая константа из этой надписи. Пример: для `Label(..., "V1s=" + String(RMS1), ...)` откроется строка вызова `Label`, а не `myGLCD.print(Caption, ...)` внутри него. Если такой строки нет, открывается сам рисующий оператор.
- Повторный клик по той же надписи в течение 3 секунд открывает строку вызова уровнем выше. Весь стек выводится в журнал сборки, выбранная строка отмечена `[ ]`.
- Обмен идёт через заголовок области отладчика, слова 13–63 (`SimDbgWhere*` в `src/sim_internal.h`). Отвечает поток хоста, поэтому клик работает и на ходу, и на остановке. Если скетч собран прежней версией ArdSim, через 1.5 с в журнале появится просьба собрать его заново.

## Ограничения

- Несколько `.ino` в папке склеиваются, как в Arduino IDE: главный файл первым, остальные по имени. Прототипы всех функций ставятся перед первой функцией главного файла. Файлы `.cpp` и `.h` папки скетча не компилируются, `.h` подключаются через `#include`.
- Модель ротора линейная и на одной скорости. Коэффициенты влияния не зависят от оборотов, радиус всех грузов равен радиусу пробного.
- Watch показывает переменные, а не выражения: `a + b`, поля структур и `obj.method()` не вычисляются.
- `SdVolume` возвращает нули, `card.type()` — 0, если `card.init()` не вызывался (как на устройстве).

## Файлы

- `include/` — заголовки для скетча: `Arduino.h`, `WString.h`, `UTFT.h`, `SD.h`, `SPI.h`, `DueTimer.h`, `avr/pgmspace.h`, `ardsim_debug.h` (отладочные вставки).
- `src/` — реализация: `sim_core.cpp` (пины, время, прерывания, таймеры, Serial), `sim_string.cpp`, `sim_utft.cpp`, `sim_sd.cpp`, `sim_signal.cpp` (генератор сигналов и тахометр), `sim_window.cpp`, `sim_host.cpp` (режим `/host` для окна Emulator unIDE), `sim_debug.cpp` (отладчик: точки, шаги, стек, значения).
- `tools/ardprep.cpp` — подготовка `.ino`: `#include "Arduino.h"`, склейка `.ino` папки, прототипы функций (как в Arduino IDE), `#line` для номеров строк в ошибках, отладочные вставки. Скрипт собирает его в `tools/ardprep2.exe` при первом запуске; номер в имени меняется вместе с `ardprep.cpp`, так что новая версия собирается сама.
- `fonts/` — шрифты-замены, `tools/make_fonts.py` — их генератор.
