Первая настройка

Имя и почта

Каждый коммит подписывается именем и почтой. Задаётся один раз для всех репозиториев:

git config --global user.name "Ваше Имя"
git config --global user.email "you@example.com"

Для GitHub почта должна совпадать с почтой учётной записи (или с её адресом вида ...@users.noreply.github.com), чтобы коммиты связывались с вашим профилем.

Полезные настройки

КомандаЧто даёт
git config --global core.editor notepadРедактор сообщений коммитов — Блокнот вместо vim.
git config --global core.quotepath offРусские имена файлов в git status выводятся буквами, а не кодами \320\220....
git config --global pull.rebase falseЕсли и у вас, и на сервере есть новые коммиты, git pull делает слияние (merge), а не останавливается с вопросом, как их совместить.
git config --global init.defaultBranch mainПервая ветка новых репозиториев называется main.

Посмотреть все настройки и откуда они взяты: git config --list --show-origin.

Концы строк (core.autocrlf)

В Windows строки кончаются CRLF, в Linux — LF. Настройка core.autocrlf: true — в репозиторий LF, в рабочую копию CRLF; false — как есть. В PortableGit она по умолчанию true. Правила в файле .gitattributes репозитория важнее этой настройки (см. .gitattributes).

Получить репозиторий

cd /d/_F/balan
git clone https://github.com/diakin/unIDE.git
cd unIDE

Создаётся папка unIDE с рабочей копией ветки по умолчанию. Начать новый репозиторий в существующей папке: git init.

Вход на GitHub

При первом git push (или pull закрытого репозитория) Git спрашивает учётные данные. Пароль от GitHub для этого не подходит: нужен вход через окно Git Credential Manager (он есть в Git for Windows) или токен (GitHub → Settings → Developer settings → Personal access tokens), который вводится вместо пароля. Данные запоминаются, и спрашиваться они больше не будут.
