.gitignore и .gitattributes

.gitignore — что не хранить

Файл .gitignore в корне репозитория (можно и в подпапках) перечисляет шаблоны файлов, которые Git не должен замечать: результаты сборки, временные файлы.

ШаблонЗначит
*.exeвсе файлы .exe в любой папке
Output/папка Output в любом месте
/build.logтолько в корне
!tools/7zip/7z.exeисключение: этот файл хранить, хотя *.exe не хранятся
# тексткомментарий

В репозитории unIDE так и сделано: *.exe и *.dll не хранятся, кроме tools/7zip/7z.exe и tools/7zip/7z.dll.

.gitignore действует только на файлы, которые Git ещё не хранит. Уже записанный файл перестаёт храниться так: git rm --cached файл, затем коммит.

Почему файл не попадает в репозиторий: git check-ignore -v путь показывает правило и файл, где оно записано.

.gitattributes — концы строк и кодировки

Правила для типов файлов: текст или двоичный, концы строк, кодировка. В репозитории unIDE для исходников Delphi и Basic записано, например:

*.pas  text eol=crlf working-tree-encoding=windows-1251
*.exe  binary
  • eol=crlf — в рабочей копии строки кончаются CRLF (как нужно Delphi 7), в репозитории хранятся с LF.
  • working-tree-encoding=windows-1251 — на диске файл в кодировке Windows-1251, а в репозитории хранится в UTF-8. Поэтому git diff, git log -p и страницы GitHub показывают русский текст исходников правильно.
  • binary — файл не сравнивается построчно и не преобразуется.

Эти правила действуют одинаково в Windows и Linux и важнее настройки core.autocrlf.
