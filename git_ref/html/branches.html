Ветки

Посмотреть

git branch            # свои ветки, текущая отмечена *
git branch -a         # и ветки сервера (remotes/origin/...)
git branch -vv        # с последним коммитом и связью с веткой сервера

Переключиться

git switch mainTest           # перейти на ветку
git switch -                  # вернуться на предыдущую
git switch -c try-qemu        # создать ветку от текущего места и перейти на неё
git switch -c try-qemu main   # создать от ветки main

Ветки только сервера (есть origin/имя, своей нет) — git switch имя создаёт свою и связывает её с серверной. Старое написание тех же команд — git checkout имя, git checkout -b новая.

Переключение с незаписанными правками: если правки не мешают, они переходят на новую ветку вместе с вами; если мешают, Git откажется переключаться — запишите их коммитом или отложите (git stash).

Слить: merge

git switch main
git merge mainTest      # влить mainTest в main

Если в main не было своих новых коммитов, main просто передвигается вперёд (fast-forward). Иначе создаётся коммит слияния. Если одни и те же строки изменены в обеих ветках — конфликт.

Удалить и переименовать

git branch -d try-qemu            # удалить слитую ветку
git branch -D try-qemu            # удалить, даже если не слита (коммиты пропадут из веток)
git push origin --delete try-qemu # удалить ветку на сервере
git branch -m старое новое        # переименовать

Схема веток unIDE: main и mainTest

Изменения накапливаются в mainTest; проверенное переносится в main; для пробных изменений создаются отдельные ветки.

# работа - в mainTest
git switch mainTest
git pull
...правки, git add, git commit...
git push

# проверенное - в main
git switch main
git pull
git merge mainTest
git push
git switch mainTest

# пробная ветка от mainTest
git switch -c try-feature mainTest
...коммиты...
git push -u origin try-feature    # на сервер (первый раз - с -u)
# удалась - влить в mainTest:
git switch mainTest
git merge try-feature
git push
git branch -d try-feature
