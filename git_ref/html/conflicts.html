Конфликты слияния

Конфликт — когда при merge, pull, rebase или stash pop одни и те же строки файла изменены по-разному. Git сливает всё, что может, а в спорных местах оставляет обе версии и ждёт решения.

Как выглядит

CONFLICT (content): Merge conflict in Unit1.pas
Automatic merge failed; fix conflicts and then commit the result.

В файле спорное место размечено:

<<<<<<< HEAD
  Caption := 'Install QEMU';        // ваша версия (текущая ветка)
=======
  Caption := 'Install QEMU 7.0.0';  // версия из сливаемой ветки
>>>>>>> mainTest

Как решить

  1. git status — файлы с конфликтами в списке «both modified».
  2. Открыть файл (в unIDE), найти <<<<<<<, оставить нужное, удалить строки-разметки <<<<<<<, =======, >>>>>>>.
  3. git add Unit1.pas — отметить, что конфликт решён.
  4. Когда решены все: git commit (для merge и pull; сообщение уже подготовлено) или git rebase --continue (для rebase).

Целиком взять одну сторону: git checkout --ours Unit1.pas (ваша) или git checkout --theirs Unit1.pas (сливаемая), затем git add. При rebase стороны наоборот: --ours — ветка, на которую переносятся коммиты, --theirs — ваши переносимые коммиты.

Передумать

git merge --abort        # отменить слияние, вернуть всё как было до него
git rebase --abort       # отменить rebase
