Git в unIDE: панель Git и меню

Команды Git в unIDE собраны в трёх местах: панель Git (вкладка Git рядом с Components над редактором), меню Repository и меню Branch. Все они работают с одним и тем же репозиторием — тем, что показан на панели. Команды git и их вывод пишутся во вкладку Git log внизу окна.

Какой репозиторий текущий: выбранный вручную (Repository → Add Local Repository, Clone, New или список кнопки Repository... на панели), иначе — тот, в котором лежит открытый проект, а без проекта — файл активной вкладки. Выбор вручную запоминается для каждого проекта отдельно.

Панель Git: строки

СтрокаЧто показывает
КнопкиFetch, Pull, Push, Commit..., History..., Refresh, Git Bash, Compare..., Merge Into..., Unmerged..., Help — см. Кнопки панели.

Путь и адрес можно выделить мышью и скопировать (Ctrl+C), двойной щелчок выделяет всё. «(выбран вручную)» — репозиторий выбран не по проекту. Правый щелчок по панели — меню Copy Local Path, Copy origin URL, Copy Branch Name.
BranchТекущая ветка. Выбор другой ветки в списке — переход на неё (git checkout). Строка origin/имя — ветка, которая есть только на сервере: при выборе создаётся локальная ветка с тем же именем, связанная с серверной. Ctrl+C — скопировать имя ветки.

Цвет: зелёный — всё совпадает, оранжевый — есть неотправленные, красный — есть незабранные. «нет ветки на сервере — Push опубликует её» — ветка пока только локальная.

ChangesСколько файлов изменено и не закоммичено (список — Commit...). Есть изменения — строка оранжевая.
StashСколько записей в stash (показывается, когда они есть).
Git statusИтог проверок: OK, Внимание или Error, подробности — в подсказке. Щелчок — полный git status и проверки с именами файлов в Git log; есть отслеживаемые файлы из .gitignore — открывается окно Tracked but Ignored. См. Проверки Git status.
Подсказка справаЧто сделала последняя команда и что сделать дальше (например «коммит сделан; не отправлено 1 — Push»).
ViewПоявляется, когда есть неотправленные или незабранные коммиты: окно сравнения ветки с её веткой на сервере (коммиты, файлы, разница).

Подсветка кнопок: красная кнопка — следующий шаг. Pull красная — на сервере есть новые коммиты; Commit... красная — есть незакоммиченные изменения; Push красная — есть неотправленные коммиты или ветки на сервере ещё нет.

Панель обновляется сама, когда меняются служебные файлы .git (в том числе после команд в Git Bash), и после каждой команды unIDE. Refresh — обновить сразу.

Merge Into...Влить текущую ветку в другую (например mainTest в main) и отправить ту на сервер.

Меню Branch

ПунктЧто делает
New Branch...Новая ветка от текущего коммита и переход на неё (git checkout -b). Имя без пробелов и символов ~ ^ : ? * [ \, не начинается с -, не кончается на / или .lock.
Switch Branch...Перейти на другую локальную ветку (git checkout). То же — выбор в списке Branch на панели.
Rename Branch...Переименовать текущую ветку (git branch -m). Ветка на сервере, если была, остаётся со старым именем; Push опубликует новое.

Discard All Changes...Отменить все незакоммиченные изменения: изменённые файлы — как в последнем коммите, новые файлы — в корзину. С подтверждением.

Restore Stash...Выбрать запись stash и вернуть её изменения в рабочие файлы (git stash pop). Запись убирается; при конфликте она остаётся.
Drop Stash...Удалить запись stash (git stash drop), с подтверждением. Изменения из неё пропадут.
Hidden Local Changes...Файлы, чьи изменения скрыты (Ignore → «Скрыть свои изменения» в окне Commit, skip-worktree): выбранный файл возвращается в список изменений (git update-index --no-skip-worktree).
Tracked but Ignored Files...Окно Tracked but Ignored: файлы, которые лежат в репозитории, хотя подходят под .gitignore.

Merge into Current Branch...Выбрать ветку (локальную или origin/...) и влить её в текущую (git merge).

Окно Commit

Список изменённых и новых файлов с флажками: в коммит идёт ровно то, что отмечено (как в GitHub Desktop). Справа — разница выбранного файла с подсветкой: добавленные строки — зелёным, удалённые — красным.

  • Строки раскрашены по виду файла. Сверху красные — то, что обычно не коммитят (exe, dcu, obj, log, tmp, bak, архивы и т. п.); они при первом показе без флажка. Дальше библиотеки, картинки, исходники, текст и настройки. Флажки над списком отмечают или снимают сразу все строки одного вида.
  • Discard Selected... (и правый щелчок → Discard Changes) — отменить изменения выделенных строк (не отмеченных флажками): файлы — как в последнем коммите, новые — в корзину.
  • Ignore... — чтобы выделенные файлы больше не предлагались к коммиту. Варианты: в .gitignore (для всех, .gitignore попадёт в коммит) — файл, все файлы с тем же расширением или папку; то же только у себя (.git/info/exclude, в репозиторий не попадает); для файлов, которые уже в репозитории, — перестать отслеживать (git rm --cached + .gitignore: файл остаётся на диске, из репозитория удаляется следующим коммитом) или скрыть свои изменения (skip-worktree: файл в репозитории остаётся, ваши правки не предлагаются; вернуть — Branch → Hidden Local Changes).
  • Заголовок (Summary) обязателен, описание — по желанию.
  • Commit — закоммитить отмеченное в текущую ветку; Commit and Push — закоммитить и сразу отправить на сервер.

Коммит не прошёл с сообщением про автора — не заданы имя и почта: git config --global user.name "Имя" и git config --global user.email почта (в Git Bash), см. Первая настройка.

Окно History

Коммиты текущей ветки (git log). У выбранного коммита — автор, дата, полный текст, изменённые файлы и разница выбранного файла. Коммиты, которые ещё не отправлены на сервер, — оранжевым. Load More — показать следующие коммиты.

КнопкаЧто делает
Copy SHAПолный SHA выбранного коммита — в буфер обмена.
View on GitHubСтраница коммита на GitHub.
New Branch from Commit...Новая ветка от выбранного коммита и переход на неё. Выполняется после закрытия окна.
Revert CommitНовый коммит, который отменяет изменения выбранного (git revert); история не переписывается. Выполняется после закрытия окна.

Compare: сравнение веток

Выбираются две ветки (локальные и origin/...). В Git log — сводка: сколько коммитов есть только в каждой ветке и какие файлы различаются (git diff --stat). Коммиты открываются в окне History в режиме сравнения: первый столбец — ветка, строки — цветом своей ветки, у каждого коммита — файлы и разница. Revert в этом режиме нет.

Merge Into: влить текущую ветку в другую

Например, работа идёт в mainTest, а готовое нужно перенести в main. Выбирается ветка, в которую вливать. Если у неё нет своих коммитов (она — предок текущей и на сервере, и локально), переключаться не нужно: текущая ветка отправляется на сервер под её именем (git push origin текущая:другая), а локальная другая ветка перематывается на тот же коммит. Иначе: переход на другую ветку, догнать сервер (pull --ff-only), git merge текущей, git push и возврат на текущую. При конфликте unIDE остаётся на другой ветке — см. Конфликты.

Unmerged: коммиты не в текущей ветке

Коммиты всех веток (локальных и origin/...), которых нет в текущей, в одной таблице; цвет строки — у каждой ветки свой. Коммит, перенесённый cherry-pick'ом с тем же содержимым, не показывается. Коммит, который есть в нескольких ветках, — одна строка, ветки через запятую.

КнопкаЧто делает
Cherry-pickПеренести выделенные коммиты в текущую ветку, от старых к новым (копии коммитов, git cherry-pick -x).
Merge BranchВлить в текущую ветку целиком ветку выделенного коммита.
Delete BranchУдалить ветку выделенного коммита — локальную и на сервере. Выделены коммиты из нескольких веток или ничего не выделено (Ctrl+щелчок снимает выделение) — ветки выбираются из списка.
CloseЗакрыть окно.

После Cherry-pick, Merge Branch и Delete Branch окно открывается снова с новым списком, пока его не закроют. Долгую загрузку списка можно прервать клавишей Esc.

Окно Clone Repository

  • Вкладка GitHub.com — список ваших репозиториев на GitHub, с фильтром по части имени; Обновить — перечитать список. Нет сохранённого логина — кнопка Войти..., см. Вход на GitHub.
  • Вкладка URL — адрес репозитория (https://github.com/владелец/имя.git) или просто владелец/имя.
  • Локальный путь — папка\имя репозитория. Он следует за выбранным репозиторием, пока его не изменили вручную. Choose... выбирает папку, в которой будет создана папка репозитория.
  • Флажок Создать проект на основе локального репозитория — после клонирования откроется окно New Project с папкой клона.
  • Clone — git clone. Папка и флажок запоминаются до следующего раза.

Если такой репозиторий у вас уже склонирован в другую папку, клон будет второй, независимой копией: Pull и коммиты в каждой папке делаются отдельно. Лишнюю копию можно убрать командой Delete Local Repository.

Удаление локального репозитория

Repository → Delete Local Repository... перемещает папку текущего репозитория в корзину целиком, вместе с файлами из .gitignore (сборки, локальные настройки). Репозиторий на сервере не трогается.

  • Перед вопросом unIDE проверяет и перечисляет, что пропадёт вместе с папкой: незакоммиченные изменения и новые файлы, коммиты, которых нет на сервере (если remote нет — все коммиты: репозиторий есть только в этой папке), записи stash. Есть что-то из этого — окно-предупреждение, кнопка по умолчанию — «Отмена».
  • Не удаляются: корень диска, папка, в которой лежит сама unIDE, папка открытого проекта. Открыты вкладки с файлами из этой папки — unIDE показывает их и просит закрыть.
  • Папка не помещается в корзину — Windows спросит, удалить ли её насовсем.
  • Файлы заняты (Git Bash, Проводник, другая программа) — папка удалится не полностью, сообщение в Git log; уже удалённое — в корзине.
  • После удаления репозиторий убирается из списка недавних, и панель снова показывает репозиторий открытого проекта.

Окно Tracked but Ignored

Файлы, которые лежат в репозитории, хотя подходят под правила .gitignore (.gitignore на уже отслеживаемые файлы не действует). Для файлов, отмеченных флажками:

  • Оставить в репозитории — в .gitignore дописывается исключение !путь, проверка Git status о файле больше не говорит;
  • Убрать из репозитория — git rm --cached: файл остаётся на диске, из репозитория уходит следующим коммитом, дальше .gitignore его не пускает.

Отмечать помогают кнопки: все, ни одного, все с тем же правилом, что у выделенной строки, вся папка выделенной строки.

Проверки Git status

УровеньЧто проверяется
ErrorНезаконченное слияние, cherry-pick, revert или bisect; файлы с конфликтом; HEAD отсоединён от ветки (выбрать ветку в списке Branch или Branch → New Branch); есть .git\index.lock — работает другой git или он завершился аварийно.
ВниманиеФайлы со скрытыми изменениями (skip-worktree, assume-unchanged): git status их не показывает, а переход на другую ветку на них останавливается; файлы, которые и в репозитории, и в .gitignore; ветка разошлась с сервером (есть и неотправленные, и незабранные коммиты — Pull, затем Push).

Конфликты: Conflicts, Auto-resolve, Continue, Skip, Abort

Если слияние (Pull, Merge, Update from Default Branch), cherry-pick или revert остановилось на конфликте, на строке Build появляются кнопки:

КнопкаЧто делает
Conflicts...Список файлов с конфликтом в Git log; выбранный файл открывается в редакторе на первом конфликте. В файле: от <<<<<<< до ======= — текущая ветка, от ======= до >>>>>>> — вливаемое. Нужно оставить правильный текст и убрать маркеры.
Auto-resolveРазрешить конфликты, где обе стороны только добавили строки в одно место (в общей версии там ничего не было): остаются обе вставки, сначала текущей ветки, потом вливаемая. Остальные конфликты остаются с маркерами — вручную.
ContinueКонфликты исправлены и файлы сохранены: отметить файлы (git add) и закончить — коммит слияния или git cherry-pick / revert --continue.
SkipПропустить этот коммит и перейти к следующему (для cherry-pick, revert, rebase).
AbortОтменить операцию: файлы и ветка — как до неё (git merge / cherry-pick / revert --abort). Для bisect — закончить его (git bisect reset).

Подробнее о конфликтах — Конфликты слияния.

Вход на GitHub

Fetch, Pull, Push и Clone по https требуют логин. GitHub не принимает пароль от аккаунта для git: вместо пароля вводится personal access token (создаётся на GitHub в Settings → Developer settings → Personal access tokens).

  • Если git не получил логин, unIDE предлагает повторить команду в окне консоли, где git спросит Username (логин GitHub) и Password (token).
  • Вариант wincred и консоль настраивает credential.helper wincred: логин сохраняется в диспетчере учётных данных Windows, и дальше команды git из unIDE проходят без консоли. Только консоль — логин придётся вводить при каждой команде, которой нужен вход.
  • В окне Clone Repository кнопка Войти... принимает логин и token, проверяет token на GitHub и сохраняет его через git. Этот же логин нужен для списка репозиториев и для создания репозитория на GitHub (New Repository).

Git log и прочее

  • Git log (вкладка внизу окна) — все команды git, которые выполнила unIDE, с папкой и выводом. Долгую команду можно прервать клавишей Esc.
  • Команды pull, merge, checkout и cherry-pick сохраняют файлы, которые подходят под .gitignore, но были убраны из репозитория в другом месте (git rm --cached): git удалил бы их с диска, unIDE возвращает их после команды.
  • ReactOS → Git Terminal (Git Bash) — Git Bash в папке открытого проекта; ReactOS → Find or Install Git — найти Git for Windows или скачать свой переносной в tools\git.
