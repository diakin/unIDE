# Правила RapidQ для препроцессора RapidQ → FreeBASIC

Источники: документация RapidQ (`rapidq_ref/html_doc/chapter3.html`, разделы 3.1 Directives и 3.2 Variables and Assignments) и тест в RapidQ 2026-10-07 (вывод ниже). Где документация и тест расходятся или правило выведено только из теста — помечено.

## Переменные без объявления

- Тип — только по суффиксу, присваиваемое значение тип не задаёт (тест 3: `c="12"` → `0`).
- Без суффикса — DOUBLE (документация; тест 1: `a=5 : a=a+0.5` → `5.5`).
- `$OPTION DIM <тип>` меняет тип по умолчанию для необъявленных (документация): BYTE, WORD, DWORD, SHORT, INTEGER, LONG, SINGLE, DOUBLE, STRING, VARIANT.
- `$TYPECHECK ON` / `$OPTION EXPLICIT` — объявление обязательно; можно включать и выключать посреди файла.
- `m` и `m$` — разные переменные (тест 13).
- Не присвоенная переменная — 0 (тест 12).
- Необъявленная числовая переменная в строковом выражении RapidQ молча пропускает (тест пользователя 2026-10-08, с rapidq.inc): `"aaa"+crlfcrlfcrlf+"bbb"` → `aaabbb`, `REPLACESUBSTR$(s, crlfcrlfcrlf, crlf)` строку не меняет. Так в conversion.inc и Files.inc годами «работали» строки вида `REPLACESUBSTR$(s, crlfcrlf, crlf)` — по словам пользователя, ошибка: нужно `crlf+crlf`; в копиях `rapidq_ref/inc` исправлено. FreeBASIC на таком выражении даёт ошибку типа; препроцессор предупреждает о каждой необъявленной переменной, которой нигде не присваивается значение (`Перем = …`, FOR, INC/DEC).
- Объявление `DIM Num$ AS INTEGER` допустимо: тип из `AS`, суффикс — часть имени (документация).

| Суффикс | Тип | Размер | FreeBASIC |
|---|---|---|---|
| `?` | BYTE | 1 | `UByte` |
| `??` | WORD | 2 | `UShort` |
| `???` | DWORD | 4 (в документации — только Linux) | `ULong` |
| `%` | SHORT | 2 | `Short` (тест 7: 70000 → 4464, перенос по 16 битам) |
| `&` | LONG = INTEGER | 4 | `Long` (не `Integer`: в FreeBASIC 64 бит он 8-байтный) |
| `!` | SINGLE | 4 | `Single` |
| `#` | DOUBLE | 8 | `Double` |
| `$` | STRING | — | `String` |
| нет | DOUBLE (или `$OPTION DIM`) | 8 | `Double` |

## Присваивания

- Строка в числовую переменную — 0, в том числе строка из цифр (тест 3) и строковая переменная (тест 16). Документация: результат не определён, «скорее всего 0». В FreeBASIC такое присваивание — ошибка компиляции; препроцессор заменяет правую часть на 0 (или вызов функции, возвращающей 0, чтобы выражение с побочными эффектами выполнилось).
- Число в строковую переменную — пустая строка (документация; тестом не проверялось).
- Дробное в целое — отбрасывание к нулю: 5.7 → 5, −5.7 → −5 (тесты 4–6). В FreeBASIC присваивание округляет (5.5 → 6, проверено на fbc 1.10.1) — нужен `Fix()`.
- Переполнение SHORT, BYTE, WORD — перенос по разрядности, без ошибки: `g%=70000` → 4464 (тест 7), `b?=300` → 44, `w??=70000` → 4464 (тест 2026-10-07). В `rqrt.bi` так же: в Compat молча, в Smart — перенос и предупреждение.
- Дробное вне диапазона LONG в `&`-переменную — RapidQ останавливает программу: `e&=3000000000` → «Exception EInvalidOp in module ... Invalid floating point operation.», без строки и имени переменной (тест 2026-10-07). В режиме Smart так не делается (см. «Режимы»).
- Переполнение в арифметике LONG — то же: `e&=2147483647 : e&=e&+1` → EInvalidOp при присваивании (тест 2026-10-07). Значит, RapidQ считает `e&+1` не в 32 битах, а с плавающей точкой, и падает уже при записи в `e&`. В FreeBASIC win32 `e__l+1` (Long + 1) считается в 32 битах и молча переходит в −2147483648 до `RqLong`: в Smart значение то же, что дал бы перенос, но без предупреждения; в Compat падения нет. В win64 сумма 64-битная — `RqLong` переносит и предупреждает.
- Объектам (QFORM и т. д.) число или строку присвоить нельзя — единственная строгая проверка (документация).
- `/` — деление с плавающей точкой (тест 2: 7/2 → 3.5).

### Как препроцессор делает присваивание

Тип выражения справа препроцессор не вычисляет: правая часть оборачивается в функцию преобразования по типу переменной слева, а нужную перегрузку по типу выражения выбирает сам fbc при компиляции (проверено на fbc 1.10.1):

```
Function RqNum Overload (ByVal Value As Double) As Double   ' число -> как есть
Function RqNum Overload (ByRef Value As String) As Double   ' строка -> 0
Function RqLong Overload (ByVal Value As Double) As Long    ' Fix: 5.7 -> 5, -5.7 -> -5
Function RqLong Overload (ByRef Value As String) As Long    ' 0
Function RqShort Overload (ByVal Value As Double) As Short   ' перенос: 70000 -> 4464
Function RqStr Overload (ByRef Value As String) As String
Function RqStr Overload (ByVal Value As Double) As String   ' число -> ""
```

`b=a` (b — DOUBLE, a — STRING, объявлена хоть за тысячу строк) → `b = RqNum(a)` → 0. Препроцессору нужен только тип переменной слева: первый проход по всем файлам программы собирает объявления (DIM, суффиксы, `$OPTION DIM`, поля TYPE, параметры и локальные DIM в SUB/FUNCTION — со своей областью видимости), второй проход переписывает присваивания.

## Строковые операции

- `s$[N]` — символ строки, счёт с 1 (operators.html: «s$[2] returns the second character»). Тест в RapidQ 2026-10-08, `S$="123456"`: `s$[0]` → `""`, `s$[1]` → `1`, `s$[8]` → `""` — вне строки пусто, без ошибки. Перевод: `RqStrIdx(s, N)` (rqrt.bi); работает и для переменных `AS STRING` без `$`.
- Запись `s[5] = "x"` RapidQ не компилирует («^-- error», тест пользователя 2026-10-08) — препроцессор тоже даёт ошибку перевода.
- `a$ - b$` — из `a$` убираются все вхождения `b$`: `"jello" - "l"` → `"jeo"` (operators.html). У `-` и `+` один приоритет, слева направо: `a + b - c` = `(a + b) - c`. Перевод: в цепочке `+ - &`, где есть строка, `a - b` → `RqStrSub(a, b)`. Вычитание с пустой строкой и числа в такой цепочке в RapidQ не проверены.
- `Перем ++` — увеличение на 1, отдельным оператором (loops.html: `I++`); перевод — `Перем += 1`. `++` внутри выражения и `--` в документации нет — не переводятся.

## SELECT CASE

- `CASE = x` — как `CASE x` (тест пользователя 2026-10-08: `x = 0`, `CASE = 0` → совпало). Так в Math.inc, QFileDialog.inc, rapidq2.inc (`CASE = "MOUS"`).
- Сравнение в CASE по документации (conditions.html) — с IS: `CASE IS > 200`; списки и диапазоны — `CASE 1 TO 4, 10 TO 20`. Так же у FreeBASIC — переводится как есть (тест caseis.bas).
- `CASE > 5` без IS в документации нет. При `x = 7` не совпало — ушло в `CASE ELSE` (тест пользователя 2026-10-08), то есть RapidQ понимает его не как сравнение; как именно — не выяснено. Препроцессор на `CASE <`, `>`, `<=`, `>=`, `<>` без IS даёт ошибку перевода с подсказкой `CASE IS > …`. `CASE = x` без IS тоже не из документации, но тест показал, что он совпадает как `CASE x`.

## TRUE и FALSE

- `TRUE` и `FALSE` — не слова RapidQ. Значение задаёт `rapidq.inc` (строки 42–43: `$define False 0`, `$define True 1`); в других include бывает `CONST True = 1`, в примере CONST документации (otherdetail.html) — `CONST True AS LONG = NOT False`, то есть -1.
- Без определения это необъявленная переменная со значением 0. Тест в RapidQ (2026-10-08), файл без include: `TRUE` → `0`, `(Not TRUE)` → `-1`, `Not TRUE` → `-1`, `False` → `0`, `Not False` → `-1`. NOT — побитовый.
- Результат сравнения даёт компилятор: -1 (operators.html: «You may assume that "true" equals -1»; тест `PRINT (2 > 1)` → `-1`). Отсюда при `$define True 1` условие `IF (a > b) = TRUE` ложно (-1 ≠ 1), а `NOT TRUE` = -2, то есть не ноль (вывод из побитового NOT; в RapidQ с rapidq.inc не проверено).
- `$define False 0`, затем `CONST False = 0` — RapidQ компилирует, `PRINT False` → `0` (тест пользователя 2026-10-08; так в rapidq2.inc, строки 54–55 и 78–79). Препроцессор: CONST, у которого имя уже заменено $DEFINE числом, пропускается; если значение CONST другое — предупреждение (что тогда даёт RapidQ, не проверено). Так же ComPort.cmp и RQdebugger (`CONST &H80 = &H80` после $define).
- Boolean-свойства компонентов (Checked, Visible, Selected…) при чтении дают 1 / 0 (сообщил пользователь, 2026-10-08).
- Перевод: `$define True 1` препроцессор подставляет при чтении строки, как любой $DEFINE; `CONST True = …` — константа `TRUE_v` (True у FreeBASIC — слово языка, равно -1). Без определения `TRUE`/`FALSE` — неявная переменная `TRUE_v`/`False_v` (0) и предупреждение при переводе, в обоих режимах. Сравнение у FreeBASIC тоже -1 — замена не нужна.

## PRINT (по тесту)

- Целое значение (в пределах LONG) — без дробной части: `5`, `3.0` → `3`.
- Дробное — ровно 9 знаков после точки: `5.500000000`, `0.333333333`, `0.300000000`, `0.000010000` (без экспоненты).
- Целое значение вне LONG — цифры и `.0`: `1e20` → `100000000000000000000.0`, `2147483648` → `2147483648.0`. В тесте 10 перед числом были пробелы, в тесте 9 — нет; правило пока не ясно.
- Перед положительным числом пробела нет (FreeBASIC ставит пробел под знак).
- Запятая между элементами ничего не вставляет: `print 5, 5.5, "end"` → `55.500000000end` (в FreeBASIC запятая — переход к следующей зоне печати).
- Итог: `PRINT` заменяется своей процедурой форматирования.
- `STR$` в RapidQ — без пробела перед положительным числом и без 9 знаков: `STR$(3)` → `3`, `STR$(-3)` → `-3`, `STR$(5.5)` → `5.5` (тест 2026-10-07). Так же работает `Str$` FreeBASIC — замена не нужна.

## Режимы: Compat и Smart

Решение пользователя (2026-10-07): поведение RapidQ копируется не везде. Там, где RapidQ падает или молча теряет данные, по умолчанию действует разумный вариант; точное поведение RapidQ — отдельный режим.

- **Compat** — как RapidQ, включая падения и молчаливые 0.
- **Smart** (по умолчанию) — программа не падает там, где можно продолжить, а ошибки сообщают подробности: файл, строку исходника RapidQ, имя переменной и значение.

| Ситуация | Compat | Smart |
|---|---|---|
| Дробное вне диапазона LONG в `&` | ошибка EInvalidOp, программа закрывается | перенос по разрядности, как у SHORT |
| Ошибка во время работы (деление, массивы, пустой объект) | сообщение RapidQ | сборка с `-exx`: сообщение fbc с файлом и строкой исходника RapidQ (через `#line`) |
| Строка в числовую переменную | 0 | 0 и предупреждение препроцессора при сборке: файл, строка, имя переменной |

Где задаётся: настройка проекта в unIDE; в исходнике — строка-комментарий `'$RQFB COMPAT` или `'$RQFB SMART` (комментарий, чтобы rc.exe RapidQ его пропускал).

Решено пользователем 2026-10-07:
- названия режимов — Compat и Smart;
- строка в числовую переменную в Smart — 0, как в RapidQ, плюс предупреждение препроцессора при сборке (не превращать `"12"` в 12);
- ошибка во время работы в Smart сообщается всеми способами сразу: окно, строка в консоль (если она есть) и запись в лог-файл рядом с exe (`<программа>_error.log`): файл и строка исходника RapidQ, имя переменной, значение, текст ошибки.

## Директивы (документация)

| RapidQ | FreeBASIC / препроцессор |
|---|---|
| `$APPTYPE CGI\|CONSOLE\|GUI` (по умолчанию GUI, без директивы RapidQ определяет сам) | ключ fbc `-s console` / `-s gui` |
| `$TYPECHECK ON\|OFF` (по умолчанию OFF) | режим препроцессора: вставлять `Dim` или нет |
| `$INCLUDE "f"` / `<f>` (не внутри SUB/FUNCTION) | `#include "f"` на нормализованную копию; `"..."` — текущая папка и пути include, `<...>` — ещё и пути окружения |
| `$RESOURCE Handle AS "file"` / `<file>` (глава 8: файл встраивается в exe; BMPHandle, ICOHandle, PlayWav, `RESOURCE(n)`, `EXTRACTRESOURCE`) | `Const Handle = 20001 + n` и файл `<главный>_res.rc` (RCDATA с тем же номером, содержимое — файл как есть), его fbc собирает в exe; поиск файла — как у `$INCLUDE`, `./` в начале убирается; имя второй раз — предупреждение, второе объявление пропускается; файл не найден — предупреждение, ресурс пустой. Номер ресурса в RapidQ не проверялся — программы его только передают |
| `$DEFINE`, `$UNDEF a, b`, `$IFDEF`, `$IFNDEF`, `$ELSE`, `$ENDIF` | `#define`, `#undef`, `#ifdef`… (`$DEFINE` — замена одного токена, не функция) |
| `$OPTION BYREF` | параметры по ссылке; по умолчанию RapidQ передаёт по значению |
| `$OPTION DECIMAL ","` | разделитель для VAL |
| `$OPTION DIM <тип>` | тип необъявленных |
| `$OPTION ICON "file.ico"` | .rc |
| `$OPTION VBDLL`, `$OPTION WEAKTYPE`, `$OPTION INKEY$`, `$OPTION BYTECODE`, `$OPTIMIZE` | по необходимости |
| `$ESCAPECHARS ON` (по умолчанию OFF; `\a \b \f \n \r \t \v \\ \" \### \xHH`) | строки с префиксом `!"..."` |
| `$MACRO name(params) definition` (перегрузка, `##`, переопределение операторов, `:` как перевод строки, область — модуль) | `#macro`/`#define` там, где совпадает; переопределение операторов и перегрузку — разворачивать препроцессором |

## Указатели на процедуры (документация: глава 11, otherdetail.html)

- `BIND переменная TO процедура` — переменная получает адрес процедуры и запоминает её число параметров (шаблон); у массива шаблон задаёт первый BIND. `CALLFUNC(переменная, параметры)` вызывает процедуру по адресу с параметрами шаблона, как оператор или как функция. Указатель на процедуру параметром передать нельзя — обход в главе 11.4: глобальная переменная-шаблон, привязанная к процедуре-шаблону, которой присваивают адрес.
- `CODEPTR(процедура)` (или `CALLBACK`) — адрес процедуры «для CALLBACK-процедур»; в документации: «Not all cases are implemented, results may vary depending on the CALLBACK and the type of parameters it receives». Про само ограничение в документации больше ничего нет.
- В include пользователя (NewWndProc.Inc, CallBack_0…8.Inc, CallBackForwarder.Inc, rapidq2.inc) для каждой процедуры строится в памяти переходник из машинного кода x86 (14 байт: `pop eax / push hFunction / push eax / mov eax, MasterCallBack_N / jmp eax`); MasterCallBack_N через BIND/CALLFUNC вызывает процедуру программы. По комментариям в этих файлах («If you use threading you cannot include another CodePtr(SUB), address is used up» в QProgress.inc; «correct codeptr bug by redirecting window messaging», «don't need to redirect this temporary Codeptr unless you are using one with 2 params» в rapidq2.inc) CODEPTR RapidQ годится не во всех случаях, когда нужна процедура для Windows; в чём именно ограничение, в документации не сказано.
- Препроцессор: в FreeBASIC SUB/FUNCTION программы — обычная процедура stdcall с параметрами ByVal, её адрес Windows принимает как есть. Поэтому `CODEPTR(Имя)` → `Cast(Integer, @Имя)`, `BIND v TO Имя` → `v = Cast(Integer, @Имя)` (у процедуры только с DECLARE — шаблон без оператора), `CALLFUNC(v, a, b)` → `Cast(Function(параметры Имя) As тип, Cast(Integer, v))(a, b)`. Тела `SetNewWndProc` (→ `RqSetWndProc`: SetWindowLong(окно, GWL_WNDPROC, адрес)), `SetNewCallBack_0…8` и `SetNewFwToCallBack` (→ возвращают сам адрес) заменяются, переходник не строится. Адреса хранятся в переменных LONG, как в RapidQ, поэтому это работает в 32-битной программе; в 64 бит адрес в LONG не помещается (fbc не собирает `Dim Shared lp As Long = Cast(Integer, @Proc)`).
- Метод своего компонента (`BIND This.BindIndex TO This.WindowProc`, `CODEPTR(This.EnumChild)` в rapidq2.inc) — ошибка перевода: у метода FreeBASIC есть скрытый параметр This, Windows его не передаст.

- Подробное описание приёма NewWndProc.Inc / CallBack_N.Inc, его ограничений и того, что делает перевод, — страница `rapidq_ref/html_doc/unide_callbacks.html` (Appendix E).

## Параметры

- По умолчанию RapidQ передаёт по значению (документация, `$OPTION BYREF`). В FreeBASIC `-lang fb` строки по умолчанию передаются по ссылке (проверено) — препроцессор ставит `ByVal` явно.
- Имена параметров в DECLARE и в заголовке SUB/FUNCTION разные: в теле действуют имена из DECLARE, имя из заголовка — необъявленная переменная (0). Тест пользователя 2026-10-08: `DECLARE SUB T (A AS LONG)`, `SUB T (B AS LONG)`, `PRINT A, B`, `T 5` → `50` (запятая в PRINT RapidQ ничего не вставляет, см. «PRINT»: A = 5, B = 0). Препроцессор: заголовок FreeBASIC — с параметрами DECLARE, имена из заголовка — локальные переменные, предупреждение. Так в обоих режимах, Smart и Compat (решение пользователя 2026-10-08: не делать имена синонимами одного параметра). Так у CallBack_2.Inc (`hFunction` / `cbIndex`), а в RQSV105b2023-13Inc-4.inc и RQdebugger — у `FileNameParse$` (`cFileName` / `FileName$`), `StrCrp`, `CrpStr1`, `CrpStr` (`key` / `keys`), `ListGridDrawCell` (`R` / `Rect`).

## TYPE (запись)

- Поля идут подряд, без выравнивания. Тест пользователя 2026-10-08: `TYPE T: S AS STRING*5: N AS INTEGER: END TYPE`, `PRINT SIZEOF(TT)` → `9` (5 + 4). Глава 7: `S AS STRING*8`, `N AS INTEGER` — WriteUDT пишет 12 байт. В документации (html_doc, из неё же собран rapidq.chm) прямо о выравнивании не сказано; глава 9.7 — только о том, что старый TYPE хранился не одним блоком, и что с появлением STRUCT это неважно. Препроцессор: `TYPE Имя` без EXTENDS → `Type Имя Field = 1`.
- `STRING*N` в записи — N байт; запись дополняется пробелами и обрезается до N, чтение даёт все N символов. Тест пользователя 2026-10-08: `TT.S = "ab"` → `[ab   ]`, LEN 5, байты 97 98 32 32 32; `TT.S = "1234567"` → `[12345]`. У FreeBASIC `String*N` — N + 1 байт, поэтому препроцессор пишет поле как N байт `Имя_rqfix(0 To N - 1) As UByte` и свойство `Имя` (RqFixGet / RqFixSet в rqrt.bi); массив таких полей с одним измерением — свойство с номером. Не работает: адрес поля (`VARPTR(TT.S)`), `MID$(TT.S, …) = …`, передача поля BYREF с изменением внутри SUB (SUB получает копию). Массив с несколькими измерениями — `String*N` FreeBASIC с предупреждением.

## Свои компоненты (TYPE … EXTENDS)

По документации (глава 10): поля, методы и события наследуются; методы и обработчики пишутся внутри TYPE; к членам внутри — через имя типа или `This` (без него имя — переменная, кроме CONSTRUCTOR); `Super.x` — член класса; обработчики `EVENT` подключаются при DIM, пользователь может заменить их своим и вызвать прежний через `Объект.InheritOnXxx`; `PROPERTY SET` вызывается при присваивании полю; `PUBLIC:`/`PRIVATE:` — только для читателя.

Выведено из компонентов в `rapidq_ref/inc`, с RapidQ не сверялось:

- Внутри TYPE присваивание полю с `PROPERTY SET` пишет значение без вызова установщика: иначе `SetXP` в QButtonXP.INC (`.Xp = value` внутри установщика) вызывал бы себя, а `TabCount` в QtabControlEx.inc и `WinDir` в QIni.inc (установщики пустые, «только чтение») не менялись бы методами компонента.
- Установщик сам значение не сохраняет: `Set_Visible` в QDebug (rapidq.inc) не пишет `Visible`, `SetTabCount` пустой.
- В CONSTRUCTOR присваивание такому полю (`Visible = 1` у QDebug) — тоже без установщика (по правилу выше; окно QDebug при DIM не показывается).
- Имя установщика можно присвоить как процедуру с параметром: `Set_Popup = 1` в RichEdPopUp.inc.
- Параметры `EVENT OnXxx(...)` могут быть указаны не все (`EVENT Canvas.OnMouseMove(X AS LONG, Y AS LONG)`).

## Объекты внутри SUB/FUNCTION (тест пользователя 2026-10-09)

- Объект, объявленный DIM внутри FUNCTION, создаётся один раз и хранит содержимое между вызовами. Функция с `DIM Mem AS QMemoryStream`, `DIM Lst AS QStringList`, `DIM N AS LONG`, три вызова с текстами `AAAA`, `BBBBBBBB`, `CC`; на входе: `Mem.Size` — 0, 4, 8; `Mem.Position` — 0, 0, 0; `Lst.ItemCount` — 0, 1, 2; `Mem.Pointer` — один и тот же адрес; после третьего вызова по адресу `CCBBBBBB`. Препроцессор: такой объект — `Static`.
- `N AS LONG` на входе — 0, 9, 9: число не сохраняется (было бы 0, 1, 2) и после первого вызова не 0. Откуда 9 — не выяснено. В переводе локальные числа, как в FreeBASIC, — 0.
- `sadd` из conversion.inc (`Mem.Write InpStr : Mem.Position = 0 : sadd = Mem.Pointer`) возвращает адрес копии строки в потоке, не `VARPTR` переменной; текст по адресу остаётся и после вызова, и после выделения других строк, до следующего вызова `sadd`, который пишет в тот же поток.
- После 4 байт данных в потоке RapidQ — не нули (`AAAA[192][6][1]`): память блока не очищается.
- Описание `sadd` и полный вывод обоих тестов — страница `rapidq_ref/html_doc/f_sadd.html` (Appendix D в contents.html, SADD в указателе и в rapidq.chm); сами тесты — `RqLcl/tofb/tests/research/sadd_test.bas`, `sadd_test2.bas`.

## VARIANT, FORMAT$, INITARRAY (datatypes.html, otherdetail.html)

- VARIANT хранит число, дробное или строку; VARTYPE: 0 — число (Byte … Long), 1 — дробное (Single, Double), 2 — строка; не присвоенный — число. Пример VARTYPE в документации: `Number1=77.0 : TstNum=Number1` → 0, `Number1=77.01` → 1 — значит, вид задаёт значение, а не тип переменной справа.
- В сложении вид выбирает левый операнд: `V1 = 101 : V2 = "99.5" : PRINT V1+V2` → `200.5`; `V1 = "101" : V2 = 99.5` → `10199.5` (datatypes.html). Другие операции, сравнения и присваивание VARIANT переменной другого типа в документации не описаны — препроцессор делает их по тому же правилу (числа — через Val, строки — через Str); с RapidQ не сверялось. PRINT VARIANT в примере — `200.5`, а не `200.500000000`, как печатается DOUBLE.
- Параметры VARIANT передаются по ссылке (глава 3.5: «except for objects, variants, udts, and arrays»).
- FORMAT$ — Format Delphi (описание типов d, e, f, g, n, m, s, x и индекса `%0:d` — в otherdetail.html). Порог научной записи у `g`: в описании — «value is greater than or equal to 0.00001», препроцессор берёт правило FloatToStrF Delphi, как у STRF$ (научная запись меньше 0.0001); с RapidQ не сверялось. Разделители, валюта у `m` — у Delphi из настроек Windows; здесь точка, запятая между тысячами и без знака валюты.
- INITARRAY(Массив, значения…) — «equivalently: `DEFINT A(1 TO 100) = {55, 234, 45, 99}`»; что с остальными элементами и с лишними значениями — не сказано.

## Адреса, память, сообщения, SHELL, QUICKSORT (otherdetail.html)

- `VARPTR(переменная)` — адрес переменной. У строки — адрес её символов: так его используют include пользователя (`MEMCPY(VARPTR(QFILEDIALOG.tmpFileName), …)` в QFileDialog.inc пишет в саму строку; `varptr(str1)` в conversion.inc — буфер для MultiByteToWideChar). `VARPTR$(адрес)` — строка по адресу (в conversion.inc: `Len(varptr$(SourseStringPtr))`), то есть до нулевого байта.
- `MEMCPY(куда, откуда, n)`, `MEMSET(адрес, байт, n)`, `MEMCMP(a, b, n)`. MEMCMP по документации возвращает 0, если содержимое **не** совпадает, иначе не 0. В rapidq2.inc и RapidFRM.inc параметром передаётся сама переменная-запись (`MEMCPY(gRQ2_MeasureItem, lParam, SIZEOF(gRQ2_MeasureItem))`, `MEMSET(DevM, 0, sizeof(DevM))`) — значит, у записи RapidQ берёт её адрес (вывод из кода, в RapidQ не проверялось).
- `SENDMESSAGE`, `POSTMESSAGE` — вызовы Windows (документация отсылает к WinAPI). `KILLMESSAGE hWnd, Message` — убрать сообщение из очереди.
- `SHELL команда` ждёт конца программы; `SHELL(команда, showCMD)` — функция, не ждёт, результат — номер процесса. Как RapidQ запускает команду (напрямую или через command.com / cmd) — в документации не сказано; в RQSV105b2023-13Inc-4.inc есть `SHELL("Start "+helppath$, 0)` — Start есть только как команда cmd (в Windows 9x — Start.exe).
- `QUICKSORT(первый, последний, ASCEND|DESCEND)` — элементы между двумя адресами; «span sort» через соседние массивы документация допускает, но не рекомендует. ASCEND и DESCEND ни в одном include не объявлены — слова RapidQ; их числовые значения неизвестны.
- `ROUND` — по документации один параметр. `ROUND(x, n)` нет ни в документации, ни в исходниках `rapidq_ref` (проверено 2026-10-08).
