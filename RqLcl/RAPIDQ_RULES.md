# Правила RapidQ для препроцессора RapidQ → FreeBASIC

Источники: документация RapidQ (`rapidq_ref/html_doc/chapter3.html`, разделы 3.1 Directives и 3.2 Variables and Assignments) и тест в RapidQ 2026-10-07 (вывод ниже). Где документация и тест расходятся или правило выведено только из теста — помечено.

## Переменные без объявления

- Тип — только по суффиксу, присваиваемое значение тип не задаёт (тест 3: `c="12"` → `0`).
- Без суффикса — DOUBLE (документация; тест 1: `a=5 : a=a+0.5` → `5.5`).
- `$OPTION DIM <тип>` меняет тип по умолчанию для необъявленных (документация): BYTE, WORD, DWORD, SHORT, INTEGER, LONG, SINGLE, DOUBLE, STRING, VARIANT.
- `$TYPECHECK ON` / `$OPTION EXPLICIT` — объявление обязательно; можно включать и выключать посреди файла.
- `m` и `m$` — разные переменные (тест 13).
- Не присвоенная переменная — 0 (тест 12).
- Объявление `DIM Num$ AS INTEGER` допустимо: тип из `AS`, суффикс — часть имени (документация).

| Суффикс | Тип | Размер | FreeBASIC |
|---|---|---|---|
| `?` | BYTE | 1 | `UByte` |
| `??` | WORD | 2 | `UShort` |
| `???` | DWORD | 4 (в документации — только Linux) | `ULong` |
| `%` | SHORT | 2 | `Short` (тест 7: 70000 → 4464, перенос по 16 битам) |
| `&` | LONG = INTEGER | 4 | `Long` (не `Integer`: в FreeBASIC 64 бит он 8-байтный) |
| `!` | SINGLE | 4 | `Single` |
| `#` | DOUBLE | 8 | `Double` |
| `$` | STRING | — | `String` |
| нет | DOUBLE (или `$OPTION DIM`) | 8 | `Double` |

## Присваивания

- Строка в числовую переменную — 0, в том числе строка из цифр (тест 3) и строковая переменная (тест 16). Документация: результат не определён, «скорее всего 0». В FreeBASIC такое присваивание — ошибка компиляции; препроцессор заменяет правую часть на 0 (или вызов функции, возвращающей 0, чтобы выражение с побочными эффектами выполнилось).
- Число в строковую переменную — пустая строка (документация; тестом не проверялось).
- Дробное в целое — отбрасывание к нулю: 5.7 → 5, −5.7 → −5 (тесты 4–6). В FreeBASIC присваивание округляет (5.5 → 6, проверено на fbc 1.10.1) — нужен `Fix()`.
- Переполнение целого — перенос по разрядности, без ошибки (тест 7).
- Дробное вне диапазона LONG в `&`-переменную — RapidQ останавливает программу: `e&=3000000000` → «Exception EInvalidOp in module ... Invalid floating point operation.», без строки и имени переменной (тест 2026-10-07). В режиме Smart так не делается (см. «Режимы»).
- Переполнение в арифметике LONG — то же: `e&=2147483647 : e&=e&+1` → EInvalidOp при присваивании (тест 2026-10-07). Значит, RapidQ считает `e&+1` не в 32 битах, а с плавающей точкой, и падает уже при записи в `e&`. В FreeBASIC win32 `e__l+1` (Long + 1) считается в 32 битах и молча переходит в −2147483648 до `RqLong`: в Smart значение то же, что дал бы перенос, но без предупреждения; в Compat падения нет. В win64 сумма 64-битная — `RqLong` переносит и предупреждает.
- Объектам (QFORM и т. д.) число или строку присвоить нельзя — единственная строгая проверка (документация).
- `/` — деление с плавающей точкой (тест 2: 7/2 → 3.5).

### Как препроцессор делает присваивание

Тип выражения справа препроцессор не вычисляет: правая часть оборачивается в функцию преобразования по типу переменной слева, а нужную перегрузку по типу выражения выбирает сам fbc при компиляции (проверено на fbc 1.10.1):

```
Function RqNum Overload (ByVal Value As Double) As Double   ' число -> как есть
Function RqNum Overload (ByRef Value As String) As Double   ' строка -> 0
Function RqLong Overload (ByVal Value As Double) As Long    ' Fix: 5.7 -> 5, -5.7 -> -5
Function RqLong Overload (ByRef Value As String) As Long    ' 0
Function RqShort Overload (ByVal Value As Double) As Short   ' перенос: 70000 -> 4464
Function RqStr Overload (ByRef Value As String) As String
Function RqStr Overload (ByVal Value As Double) As String   ' число -> ""
```

`b=a` (b — DOUBLE, a — STRING, объявлена хоть за тысячу строк) → `b = RqNum(a)` → 0. Препроцессору нужен только тип переменной слева: первый проход по всем файлам программы собирает объявления (DIM, суффиксы, `$OPTION DIM`, поля TYPE, параметры и локальные DIM в SUB/FUNCTION — со своей областью видимости), второй проход переписывает присваивания.

## PRINT (по тесту)

- Целое значение (в пределах LONG) — без дробной части: `5`, `3.0` → `3`.
- Дробное — ровно 9 знаков после точки: `5.500000000`, `0.333333333`, `0.300000000`, `0.000010000` (без экспоненты).
- Целое значение вне LONG — цифры и `.0`: `1e20` → `100000000000000000000.0`, `2147483648` → `2147483648.0`. В тесте 10 перед числом были пробелы, в тесте 9 — нет; правило пока не ясно.
- Перед положительным числом пробела нет (FreeBASIC ставит пробел под знак).
- Запятая между элементами ничего не вставляет: `print 5, 5.5, "end"` → `55.500000000end` (в FreeBASIC запятая — переход к следующей зоне печати).
- Итог: `PRINT` заменяется своей процедурой форматирования.

## Режимы: Compat и Smart

Решение пользователя (2026-10-07): поведение RapidQ копируется не везде. Там, где RapidQ падает или молча теряет данные, по умолчанию действует разумный вариант; точное поведение RapidQ — отдельный режим.

- **Compat** — как RapidQ, включая падения и молчаливые 0.
- **Smart** (по умолчанию) — программа не падает там, где можно продолжить, а ошибки сообщают подробности: файл, строку исходника RapidQ, имя переменной и значение.

| Ситуация | Compat | Smart |
|---|---|---|
| Дробное вне диапазона LONG в `&` | ошибка EInvalidOp, программа закрывается | перенос по разрядности, как у SHORT |
| Ошибка во время работы (деление, массивы, пустой объект) | сообщение RapidQ | сборка с `-exx`: сообщение fbc с файлом и строкой исходника RapidQ (через `#line`) |
| Строка в числовую переменную | 0 | 0 и предупреждение препроцессора при сборке: файл, строка, имя переменной |

Где задаётся: настройка проекта в unIDE; в исходнике — строка-комментарий `'$RQFB COMPAT` или `'$RQFB SMART` (комментарий, чтобы rc.exe RapidQ его пропускал).

Решено пользователем 2026-10-07:
- названия режимов — Compat и Smart;
- строка в числовую переменную в Smart — 0, как в RapidQ, плюс предупреждение препроцессора при сборке (не превращать `"12"` в 12);
- ошибка во время работы в Smart сообщается всеми способами сразу: окно, строка в консоль (если она есть) и запись в лог-файл рядом с exe (`<программа>_error.log`): файл и строка исходника RapidQ, имя переменной, значение, текст ошибки.

## Директивы (документация)

| RapidQ | FreeBASIC / препроцессор |
|---|---|
| `$APPTYPE CGI\|CONSOLE\|GUI` (по умолчанию GUI, без директивы RapidQ определяет сам) | ключ fbc `-s console` / `-s gui` |
| `$TYPECHECK ON\|OFF` (по умолчанию OFF) | режим препроцессора: вставлять `Dim` или нет |
| `$INCLUDE "f"` / `<f>` (не внутри SUB/FUNCTION) | `#include "f"` на нормализованную копию; `"..."` — текущая папка и пути include, `<...>` — ещё и пути окружения |
| `$RESOURCE Handle AS "file"` | .rc файл |
| `$DEFINE`, `$UNDEF a, b`, `$IFDEF`, `$IFNDEF`, `$ELSE`, `$ENDIF` | `#define`, `#undef`, `#ifdef`… (`$DEFINE` — замена одного токена, не функция) |
| `$OPTION BYREF` | параметры по ссылке; по умолчанию RapidQ передаёт по значению |
| `$OPTION DECIMAL ","` | разделитель для VAL |
| `$OPTION DIM <тип>` | тип необъявленных |
| `$OPTION ICON "file.ico"` | .rc |
| `$OPTION VBDLL`, `$OPTION WEAKTYPE`, `$OPTION INKEY$`, `$OPTION BYTECODE`, `$OPTIMIZE` | по необходимости |
| `$ESCAPECHARS ON` (по умолчанию OFF; `\a \b \f \n \r \t \v \\ \" \### \xHH`) | строки с префиксом `!"..."` |
| `$MACRO name(params) definition` (перегрузка, `##`, переопределение операторов, `:` как перевод строки, область — модуль) | `#macro`/`#define` там, где совпадает; переопределение операторов и перегрузку — разворачивать препроцессором |

## Параметры

- По умолчанию RapidQ передаёт по значению (документация, `$OPTION BYREF`). В FreeBASIC `-lang fb` строки по умолчанию передаются по ссылке (проверено) — препроцессор ставит `ByVal` явно.
