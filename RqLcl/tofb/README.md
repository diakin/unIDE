# RqToFb — перевод исходников RapidQ в FreeBASIC

Препроцессор перед fbc: программа RapidQ (главный .bas и все `$INCLUDE`) переводится в файлы FreeBASIC в отдельную папку, затем собирается fbc с `-i RqLcl\inc` (там `rqrt.bi` и `rqlcl.bi`). Правила — `../RAPIDQ_RULES.md`.

## Файлы

- `RqToFb.pas` — модуль без VCL (Delphi 7 / FPC `-Mdelphi`): `RqToFbConvert(главный файл, опции, сообщения, результат)`. Подключён в unIDE: рамка Project, список rc.exe / FB Smart / FB Compat для программы RapidQ (`CompileRapidQFb` в Unit1).
- `rqtofbcli.dpr` — консольная утилита: `rqtofbcli <главный.bas> <папка вывода> [smart|compat] [папки include через ;]`. Пишет сообщения, затем `APPTYPE=`, `MODE=`, `OUT=`, `ERRORS=`/`WARNINGS=`; код 1 — были ошибки.
- Строка `'$RQFB SMART` или `'$RQFB COMPAT` в исходнике (комментарий — rc.exe её пропускает) задаёт режим сильнее настройки.
- `../inc/rqrt.bi` — функции, которые вставляет перевод: `RqNum`/`RqLong`/`RqShort`/`RqByte`/`RqWord`/`RqDword`/`RqSng`/`RqStr` (присваивание), `RqFmt` (PRINT), сообщения об ошибках (окно, stderr, `<программа>_error.log`), режимы `RQ_SMART`/`RQ_COMPAT`.
- `tests/` — проверочные программы и ожидаемый вывод (`*_expected.txt`; для `types16` — вывод самого RapidQ).

## В unIDE

- Рамка Project для программы RapidQ: список **rc.exe / FB Smart / FB Compat** и, для FB, разрядность 32/64. Выбор запоминается для главного .bas (editor.ini `[RapidQ.Build]`, разрядность — `[FreeBASIC.Build]`).
- IDE Options → Compilers → RapidQ Basic → **RqLcl folder** — папка `RqLcl` из исходников unIDE (пустое поле — `RqLcl` рядом с exe редактора). Компилятор fbc — из IDE Options → Compilers → FreeBASIC.
- Compile: перевод в `<папка главного .bas>\_rqfb`, сообщения перевода в лог; затем fbc `-s gui|console` (по `$APPTYPE`), `-exx` в Smart, `-i RqLcl\inc`; exe рядом с главным .bas; `rqlcl32.dll`/`rqlcl64.dll` копируется рядом с exe. Ошибки fbc указывают на строки исходника RapidQ — двойной щелчок открывает их.
- Отладчик RapidQ (F7/F8/F4, точки останова) при сборке через FreeBASIC не работает — сообщение в логе.

## Как устроен перевод

- Строки переводятся один к одному; перед ними `#line 0 "исходный файл"` — ошибки fbc и сообщения программы указывают на файл и строку исходника RapidQ. Оператор, собранный заново (DIM, заголовок SUB), сохраняет число строк продолжениями ` _`.
- Два прохода в порядке включения файлов: первый собирает объявления и необъявленные переменные, второй пишет текст.
- `$DEFINE`, `$UNDEF`, `$IFDEF`/`$IFNDEF`/`$ELSE`/`$ENDIF` выполняет сам препроцессор (в RapidQ ими меняют и ключевые слова, как в `rapidq.inc`); `#define` в начале строки — то же, что `$DEFINE`.
- Переменная модуля — `Dim Shared`; необъявленные — в заголовке главного файла; необъявленная внутри SUB, которой нет в модуле, — `Dim` в строке заголовка SUB.
- Имена с суффиксом: `a$` → `a__s`, `a%` → `a__sh`, `a&` → `a__l`, `a!` → `a__f`, `a#` → `a__d`, `a?` → `a__b`, `a??` → `a__w`, `a???` → `a__dw`; имя, совпадающее со словом FreeBASIC, — с `_v`.
- Присваивание переменной: `x = выражение` → `x = RqXxx(выражение, "x", __FILE__, __LINE__)` по типу x; строка в число и число в строку — предупреждение при переводе.
- `PRINT a; b, c` → `Print RqFmt(a); RqFmt(b); RqFmt(c)`; `?` — то же.
- Параметры — `ByVal`, кроме `BYREF`, `$OPTION BYREF`, объектов, массивов и TYPE; `SUB` без параметров после `DECLARE SUB` с параметрами берёт их из DECLARE.
- `Объект.OnXxx = Процедура` → `@Процедура`; в `rqlcl.bi` обработчики и с `Sender`, и без него.
- `Result =` в функции → `Function =`; `INC x[, n]` / `DEC` → `x += n` / `x -= n`; `CALL`, `LET` убираются; `'$...` и `' $...` в комментарии → `''$...` (иначе fbc принимает за метакоманду; `' $` fbc тоже читает как метакоманду, проверено).
- Параметр или локальная переменная с именем константы модуля (`CONST clR` и параметр `Clr` в rapidq.inc) — с `_p`: в RapidQ параметр перекрывает константу, в FreeBASIC это ошибка.
- `Объект.Cell(c, r) = x` → `Объект.SetCell(c, r, x)` (у свойства FreeBASIC один индекс); таблица `RqIndexedSetText`.
- CREATE … END CREATE (документация RapidQ, гл. 5.6–5.7): `CREATE Имя AS Класс` → `DIM Имя AS Класс` (на уровне модуля — `Dim Shared`); у вложенного CREATE — `Имя.Parent = Внешний`, у пункта меню внутри меню — `Внешний.AddItems Имя`; слово в начале оператора внутри блока, если это свойство, метод или событие класса, получает имя объекта (`Caption = "x"` → `Форма.Caption = "x"`, `Center` → `Форма.Center`, `OnClick = Proc` → `Кнопка.OnClick = @Proc`, `Cell(0, 0) = "#"` → `Таблица.SetCell(0, 0, "#")`); `AddOptions = a, b, c` (метод через `=`) → `Таблица.AddOptions a, b, c`; `END CREATE` убирается. Список свойств и методов классов — константа `RqClassMembersText` в RqToFb.pas, её создаёт `gen_members.py` из документации (`rapidq_ref/html_doc`) и типов `RqLcl/inc/*.bi`. Класса нет в списке и это не свой компонент (TYPE … EXTENDS) — словом объекта считается всё, что не переменная, не процедура и не ключевое слово; один раз на класс — предупреждение.
- Обработчик события с параметрами (`Объект.OnKeyDown = Proc` и др.): заголовок `Proc` и его `DECLARE` получают типы параметров события (`Key AS WORD` → `ByRef Key As Long`, `Col%` → `ByVal Col As Long`, `Rect AS QRect` → `ByRef Rect As QRECT`); таблица `RqEventSigText`.
- Внутри CREATE `Font.Name = "Arial"` (свойство-объект класса) → `Объект.Font.Name = "Arial"`; у своего компонента (TYPE … EXTENDS, `$DEFINE QRICHEDIT QMAXEDIT`) вид слова берётся по его полям и методам и по классу RapidQ, от которого он унаследован. QPOPUPMENU внутри CREATE формы — без Parent (элемент получает меню через `PopupMenu = Имя`); невидимые компоненты — без Parent.
- `~` в именах RapidQ (`~SrcD`, `~tmp$`) → `_T_` (`_T_SrcD`).
- `.Pointer` → `.PointerAddr` (`Pointer` в FreeBASIC — ключевое слово); таблица `RqMemberMapText`.
- Параметр STRING у `DECLARE … LIB` (с BYVAL, BYREF или без) → `ByVal Имя As ZString Ptr`: RapidQ передаёт функции DLL указатель на строку (документация, глава 9). `ByVal As String` в fbc 1.10 передаёт саму строку (у `CreateEventA` с параметром STRING компоновщик искал `CreateEventA@24` вместо `@16`).
- GOSUB/RETURN (в FreeBASIC `-lang fb` GOSUB нет): `GOSUB Метка` → `RqGosubPush(стек(), вершина, N): Goto Метка`, на новой строке — метка возврата `rqgs_retN:` (перед ней `#line`, номера строк исходника не сдвигаются; оператор после `:` в той же строке идёт сразу за меткой возврата); `RETURN` → `On RqGosubPop(стек(), вершина, __FILE__, __LINE__) Goto rqgs_ret1, rqgs_ret2, …` — все GOSUB этой SUB или модуля. Стек номеров свой у модуля (`rqgs_mstk`, в заголовке главного файла) и у каждой SUB/FUNCTION (`rqgs_stk`, локальный: в рекурсии у каждого вызова свой); функции — в `rqrt.bi`. RETURN без GOSUB во время работы: Smart — предупреждение, программа идёт дальше со следующего оператора; Compat — сообщение и конец программы (как в RapidQ — не проверено). RETURN в SUB, где нет GOSUB, — предупреждение при переводе.
- `SLEEP n` → `RqSleep n`: в RapidQ n — секунды (можно дробь, consoledetail.html), у `Sleep` FreeBASIC — миллисекунды. Свой `DECLARE SUB Sleep LIB "kernel32"` (ComPort.cmp) не трогается.
- `DIR$(маска, атрибуты)` / `DIR$` → `RqDir` (rqrt.bi, FindFirstFile Windows) и `FileRec` (FileName, ShortName, Date, Time, Size, FileTime); атрибуты — как у FindFirst Delphi: обычные файлы всегда, скрытые, системные, папки — по битам &H2, &H4, &H10. Date — `MM-DD-YYYY`, Time — `HH:MM:SS` (местное время): формат RapidQ не проверен, RQdebugger разбирает Date как месяц-день-год.
- Глобальные объекты RapidQ `Application`, `Screen` (→ `Screen_v`), `Clipboard`, `FileRec` объявлены заранее (в rqlcl.bi / rqrt.bi) — препроцессор не заводит для них переменные.
- Невидимые компоненты (QTIMER, диалоги, QSTRINGLIST…) внутри CREATE — без Parent (список `RqNonVisualText`).
- `.Свойство = x` внутри `WITH Объект` — как `Объект.Свойство = x` (`.OnClick = Proc` → `@Proc`).
- Продолжение строки `_` с комментарием после него (`dwFlags AS DWORD, _ '[IN] ...` в ComPort.cmp) — тоже продолжение.
- `INC(x, n)` со скобками и `INC This.Поле` — как `INC x, n`. Объявленная переменная с именем слова RapidQ (параметр `line`) — переменная.
- `Объект.AddItems a, b, c, d, e…` (и `AddTabs`, `AddPanels`, `AddColumns`, `DelItems`, `AddStyles`/`DelStyles`, `AddOptions`/`DelOptions`) с числом параметров больше 4 делится на несколько вызовов по 4: у перегрузок в `rqlcl.bi` параметров не больше 4 (меню, номера) или 6 (строки).
- Предупреждение «не объявлена и нигде не получает значение — в RapidQ всегда 0 / ""»: необъявленная переменная, которой нет слева от `=`, в FOR, INC/DEC. Ловит опечатки вроде `REPLACESUBSTR$(s, crlfcrlf, crlf)` (нужно `crlf+crlf`); то же предупреждение получают имена из отсутствующих include и из конструкций, которые препроцессор ещё не понимает ($RESOURCE, `Private Type`, `Private Declare`).
- `s$[N]` → `RqStrIdx(s$, N)` (символ с 1, вне строки — `""`), запись `s$[N] = x` — ошибка перевода (RapidQ её тоже не компилирует); `a$ - b$` → `RqStrSub(a$, b$)` в цепочке `+ - &` со строкой; `Перем ++` → `Перем += 1`. Правила — RAPIDQ_RULES.md, «Строковые операции».
- `$RESOURCE Имя AS "файл"` → `Const Имя = 20001 + n` и файл `<главный>_res.rc` в папке вывода (RCDATA, строки через CR LF — с одним LF GoRC ресурсов не видит). В выводе rqtofbcli — строка `RC=путь`; .rc передаётся fbc вторым файлом (unIDE так и делает). `RESOURCE(n)`, `RESOURCECOUNT`, `EXTRACTRESOURCE` → функции rqrt.bi.
- `CASE = x` → `CASE x`; `CASE > x` и другие сравнения — ошибка перевода (в RapidQ это не сравнение, см. RAPIDQ_RULES.md).
- `PRIVATE` / `PUBLIC` перед CONST, TYPE, DECLARE, SUB, FUNCTION, DIM убираются (`Private Type POINTAPI`, `Private Declare Function …` в Form.inc).
- `CONST Имя = …`, когда `Имя` уже заменено `$DEFINE` числом (`$define False 0` … `CONST False = 0`), пропускается, как это молча делает RapidQ; при другом значении — предупреждение.
- `TRUE`/`FALSE` — как в RapidQ, где это не слова языка: `$define True 1` из rapidq.inc подставляется как любой $DEFINE; `CONST True` — константа `TRUE_v`; без определения — неявная переменная `TRUE_v` (0) и предупреждение. Слово FreeBASIC `True` (-1) в переводе не появляется.
- `Объект.Delete` → `Объект.Delete_v` (Delete — слово FreeBASIC; QIMAGELIST.Delete), `Image.Pixel(x, y) = c` → `Image.SetPixel(x, y, c)`.
- `List.SubItem(i, j) = s` (QLISTVIEW) → `List.SetSubItem(i, j, s)`, как `Cell` у таблицы (`RqIndexedSetText`).
- `Socket.Type` → `Socket.Type_v`, `Socket.Peek` → `Socket.Peek_v` (QSOCKET; слова FreeBASIC). `Printer` — глобальная переменная (как Screen, Clipboard); QBITMAP и QNOTIFYICONDATA внутри CREATE — без Parent. Переменная или параметр `Pos` → `Pos_v` (функция FreeBASIC).
- `AddLines`, `DelLines` (QOUTLINE), `AddSections` (QHEADER) с любым числом параметров делятся на вызовы по четыре, как `AddItems`. `Объект.WndProc = Процедура` — как событие OnXxx (`@Процедура`), параметры обработчика — `(ByVal Hwnd As Long, ByVal Msg As Long, ByVal wParam As Long, ByVal lParam As Long)` (`Hwnd&` и `AS INTEGER` в заголовке SUB тоже). Типы параметров обработчиков: `OnScroll` — `(ByVal ScrollCode As Long, ByVal ScrollPos As Long)`, `OnDrawSection` — `(Index, Pressed, ByRef Rect AS QRECT)`, `OnSectionClick`, `OnSectionResize` — `(Index)`, `OnSectionTrack` — `(Index, Width, State)`, все целые ByVal.
- Обработчик `OnChange` у QLISTVIEW получает типы `(ByVal Index As Long, ByVal Change As Long)` (`Change AS BYTE` в заголовке SUB заменяется), у QTREEVIEW — `(ByVal Index As Long)`, у остальных классов OnChange без параметров. Класс берётся из объявления переменной слева (`SubsListBox(i).OnChange = Proc`); в RqEventSigText для QLISTVIEW — имя `LVONCHANGE`. `OnColumnClick` — `(ByVal Column As Long)`, `OnKeyPressed` — как OnKeyPress.

### SUBI и FUNCTIONI (документация RapidQ, глава 9)

- `SUBI Имя(...)` / `FUNCTIONI Имя(...) AS тип` (и `DECLARE SUBI`, методы SUBI своих компонентов) → `Sub Имя(ByRef RqParams As RqPList)`. Вызов `Имя "a", 5, x$` или `Имя("a", 5)` → `Имя(RqPList().Arg("a").Arg(5).Arg(x__s))`: временный список живёт до конца оператора, строка или число — выбирает перегрузка `Arg` (`rqrt.bi`). Вызов без параметров → `Имя(RqPList())`; FUNCTIONI внутри выражения и вложенная (`FindMax(1, FindMax(2, 3))`) — так же.
- Внутри: `ParamStrCount` → `RqParams.StrCount`, `ParamValCount` → `RqParams.ValCount`, `ParamStr$(i)` → `RqParamStr(RqParams, i, __FILE__, __LINE__)`, `ParamVal(i)` → `RqParamVal(...)`. Номер вне списка — пустая строка или 0, в Smart ещё и предупреждение (что делает RapidQ — не проверено).
- Метод SUBI своего компонента: вызов `Объект.Метод a, b` / `This.Метод(a, b)` распознаётся, если объект — переменная этого компонента или `This`; `A.B.Метод` — нет.

### Свои компоненты: TYPE … EXTENDS (документация RapidQ, глава 10)

- `TYPE Имя EXTENDS Класс` (и `TYPE Имя AS Класс` из главы 10.5) … `END TYPE` → `Type Имя Extends Класс` FreeBASIC. Type целиком (поля и `Declare` всех методов, собранные в первом проходе) выводится в строке `TYPE`, после него `#line` возвращает нумерацию строк исходника; тела методов — на своих местах, как `Sub Имя.Метод(...)`.
- Поле — поле Type. Поле с `PROPERTY SET Установщик` → значение `RqVal_Поле` и свойство FreeBASIC `Поле`: снаружи запись вызывает установщик, чтение даёт значение; внутри TYPE `Имя.Поле = x` пишет значение без вызова установщика (иначе установщик, который сам пишет поле, как `SetXP` в QButtonXP.INC, вызывал бы себя). Поле `AS EVENT(Шаблон)` → `Any Ptr`; `CALLFUNC(Имя.Поле, параметры)` → вызов по типу шаблона (`DECLARE SUB Шаблон`).
- `SUB`, `FUNCTION`, `PROPERTY SET` внутри TYPE — методы; `Result = x` и `Имя.Функция = x` в функции — `Function = x`. Методы с именами, которыми член Type FreeBASIC называться не может (`Delete`, `Swap`, `Type`, `Select`, `Case`, `New`, `Return` проверены), — с `_v` (и снаружи: `Edit.Delete` → `Edit.Delete_v`); суффикс — частью имени (`Err$` → `Err__s`).
- `CONSTRUCTOR` → `Constructor`; внутри него член компонента без имени объекта (`Caption = "x"`, `GetIniPath`) и свойство класса RapidQ в начале оператора (`Height = 26`) получают `This.`.
- `Имя.x`, `This.x`, `.x` внутри `WITH Имя` / `WITH This` (в том числе WITH на уровне TYPE вокруг методов) → `This.x`; `Super.x` → `Base.x`. `WITH Имя`, `WITH This`, `PUBLIC:`, `PRIVATE:`, `PROTECTED:` убираются (все члены открыты).
- `EVENT OnXxx [(параметры)]` → метод `InheritOnXxx` (вызов `Объект.InheritOnClick` из обработчика пользователя — как в главе 10.4), `EVENT Поле.OnXxx` → метод `RqEv_Поле_OnXxx`. Типы параметров — по событию (`RqEventSigText`), имена — из заголовка, их может быть меньше. Обработчик подключается в начале конструктора через переходник — процедуру модуля с `Sender`, которая вызывает метод объекта (для поля — по смещению поля `OffsetOf`). Присваивание пользователя `Объект.OnClick = Proc` заменяет его.
- `Поле.OnXxx = Имя.Метод` внутри TYPE (метод компонента как обработчик, RichEdPopUp.inc) → переходник того же вида.
- Внутри метода переменная, процедура или функция модуля с именем члена компонента или его класса (`Left$(...)` у наследника QFORM, переменная `Caption`) — с `..` (FreeBASIC внутри метода сначала ищет член; проверено, fbc 1.10.1).
- Обработчик события с параметром своего компонента (`SUB btnClick(Sender AS QButtonXP)`): событие объявлено в классе RapidQ (`Sender As QBUTTON`), поэтому параметр — того класса, а внутри — ссылка `Dim ByRef Sender As QButtonXP` на тот же объект.
- `CREATE x AS СвойКомпонент`: Parent и свойства — по классу RapidQ, от которого он унаследован, и по его собственным полям и методам; у наследников QOBJECT — без Parent.
- В заголовке главного файла: `#include once "rqrt.bi"`, `"rqstream.bi"`, `"rqlcl.bi"`.

### BIND, CALLFUNC, CODEPTR (документация RapidQ, глава 11)

`BIND v TO Proc` → `v = Cast(Integer, @Proc)` и запоминается процедура-шаблон переменной (по имени переменной или поля; собирается в первом проходе, поэтому CALLFUNC может стоять в тексте раньше BIND). `CALLFUNC(v, a, b)` и `CALLFUNC v, a, b` → `Cast(Function(параметры Proc) As тип, Cast(Integer, v))(a, b)`. `CODEPTR(Proc)` / `CALLBACK(Proc)` → `Cast(Integer, @Proc)`. BIND к процедуре только с DECLARE (шаблон `FuncBind_4` в CallBack_4.Inc) — без оператора. Функции-переходники из NewWndProc.Inc, CallBack_N.Inc, CallBackForwarder.Inc, rapidq2.inc — `SetNewWndProc`, `SetNewCallBack_0…8`, `SetNewFwToCallBack` — получают тело одной строкой (`RqSetWndProc` из rqrt.bi или сам адрес), их тело с машинным кодом x86 пропускается (в выводе — комментарием), в лог — Info. Только 32 бит. Метод своего компонента в BIND и CODEPTR — ошибка перевода. Подробно — RAPIDQ_RULES.md, «Указатели на процедуры».

## Функции RapidQ (rqrt.bi)

По `rapidq_ref/html_doc/otherdetail.html`, проверено на примерах оттуда (`tests/funcs.bas`):
FIELD$, REPLACESUBSTR$, INSERT$, DELETE$, REPLACE$, REVERSE$, CONVBASE$, HEX$ (8 знаков, как в Windows-версии RapidQ) — препроцессор переименовывает в `RqField`, `RqReplaceSubStr`, … ; RINSTR, TALLY, ROUND (половина — от нуля), CEIL, FLOOR, FILEEXISTS, DIREXISTS, SHOWMESSAGE, MESSAGEBOX, MESSAGEDLG — под теми же именами. STRF$(значение, формат, точность, знаков) → `RqStrF`: по описанию в otherdetail.html и правилам FloatToStrF Delphi (0 ffGeneral, 1 ffExponent, 2 ffFixed, 3 ffNumber; ffGeneral с порядком, если цифр до точки больше точности или значение меньше 0.0001; ffFixed/ffNumber при числе цифр до точки больше точности — как ffGeneral; половина — от нуля). Разделители — точка и запятая между тысячами. С RapidQ не сверялось: `tests/strf_expected.txt` — ожидаемое по правилам Delphi; `tests/strf.bas` можно собрать rc.exe и сравнить. Больше 17 значащих цифр Double не даёт — дальше нули (у Delphi там цифры двоичного хвоста).

## Пока не сделано

- `$MACRO`, VARIANT, LPRINT, PRINT USING. У `$RESOURCE` — нет PlayWav.
- Шаблоны TYPE (`TYPE Имя<Тип> EXTENDS QOBJECT`), `TYPE` внутри своего компонента, `Объект.Поле.InheritOnXxx`, `OnXxx = This.Поле.InheritOnXxx`; PROPERTY SET у поля-объекта или массива — обычное поле (предупреждение).
- Обработчик с Sender своего компонента, назначенный элементу другого класса (`DirTreeOnClick(Sender AS QButtonXP)` у QDIRTREE): типы не совпадают, fbc выдаёт ошибку.
- CREATE внутри SUB: объект — локальная переменная SUB (в RQdebugger так не встречается).
- Свойства и методы внутри CREATE только в начале оператора: в `IF x THEN Caption = "a"` Caption не получит имя объекта.
- Классы RapidQ, которых ещё нет в RqLcl: QCOLORDIALOG, QMYSQL, QGLASSFRAME, DirectX и др. (список — в проектном документе «RapidQ: не сделано»).
- Функции RapidQ PARAMSTR$, GET$, VARPTR$, FORMAT$ и подобные; присваивание свойству объекта числа или строки — без преобразования.
- Передача по ссылке через `@` при вызове (предупреждение, параметр получает копию).
- Числовые метки (`100 PRINT …`, `GOTO 100`, `GOSUB 100`): fbc `-lang fb` их не принимает (error 146, проверено). `ON … GOSUB`, `RETURN Метка`. GOSUB в однострочном IF не последним оператором (`IF x THEN GOSUB A : y = 1`, `IF x THEN GOSUB A ELSE …`) — ошибка перевода: метка возврата встаёт на новую строку, и остаток строки оказался бы вне IF.
