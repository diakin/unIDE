Источник разбора: **RQdebugger853-8.bas** из файлов проекта (21 654 строки). Файла RQdebugger854-0.bas нет ни в репозитории unIDE (во всех ветках только RQdebugger844-40.bas), ни в файлах проекта. Когда 854-0 появится в rapidq_ref/, отличия нужно сверить и поправить разделы 1 и 3.

## 1. Как устроено в RQdebugger853-8

Всё общение с платами идёт через **arduino-cli.exe**. Общая схема одна для всех команд: текст команды пишется в .bat (clicmd.bat, clihlp.bat, bat.bat), .bat запускается через SHELL/RUN, вывод перенаправляется в текстовый файл, затем IDE ждёт файл (опрос размера или файл-маркер) и разбирает его построчно.

### 1.1. Режим Basic / Arduino
- Два переключателя `BasicRBtn` / `ArduinoRBtn` на панели `Arduino_BasicTab` (стр. 5330–5352), обработчик `ArdBasTabChange` (17750).
- В режиме Arduino прячется `RunDebugBar` (Run, Debug, Watch, FB) и показывается `ArduinoBar`.
- При переключении: генерируется `serial.VBS` (WMI, `Win32_SerialPort`), запускается через `serial.bat`, результат в `serialList.txt`. По нему ищется порт загрузчика Bossa (Arduino Due) и строка «STMicroelectronics Virtual COM Port» (ветка для STM пустая). Ожидание файла — фиксированный `sleep 1`.
- Затем `BoardCmbBoxOnChange` (`board list`) и `ShowAllBoardList`.

### 1.2. Панель ArduinoBar (5499–5600)
- Кнопки **Verify** (`VerifyArduinoSketch`) и **Upload** (`UploadArduinoSketch`).
- Подписи Port / Board / FQBN.
- `BoardComboBox` — подключённые платы, элемент вида `FQBN/Port/Board/Core`; выбор разбирается в `BoardCmbBoxOnChange1` (17924) в глобальные `FQBN$`, `PortName$`, `BoardName$`, `Core$`.
- `FQBNCmbox` — все известные FQBN (из `BoardListAllKnown.txt`); выбор подменяет FQBN у текущей строки `BoardComboBox` (`FQBNCmboxOnChange`, 20725). Нужен для плат, которые `board list` показывает как Unknown.
- `ArduinoToolsCmbox`: Board manager, Library manager, Serial monitor, STM32CubeProgrammer.exe (`ArduinoToolsCmboxOnChange`, 18130).

### 1.3. Verify / Upload (17537–17743)
- Проверка расширения (.ino / .pde), `SaveIDEOptions`, сохранение файла.
- Если FQBN пуст или плата Unknown — модально открывается Board Manager (после закрытия сборка идёт дальше в любом случае).
- Команда Verify:
  `arduino-cli compile -e -b <FQBN> --warnings <W> --log-level <L> --build-path <BuildPath> --libraries <LibPath> --log-file <LogFile> <папка скетча> 1>CompileMsg.txt 2>&1`, второй строкой .bat — `echo ardfin1 > ardfin` (файл-маркер конца).
- Upload — та же команда с `--upload --port <PortName>`; в этой ветке `--warnings` и `--log-level` указаны дважды, а лог пишется в фиксированный `CompileMsg.log`, а не в файл из настроек.
- Ожидание: цикл до 200 проходов с `sleep 0.3` (около минуты), на каждом проходе `CompileMsg.txt` перечитывается в `ArdLogEdit`. Если маркер не появился — выход без сообщения.
- Если в выводе есть «Platform not found» — вопрос и `core install <FQBN>`. Аргументом передаётся FQBN целиком; по описанию arduino-cli у `core install` аргумент — ID платформы (`packager:arch`).
- Переходов от строки ошибки к строке исходника нет: `ArdLogEdit` — просто текст.

### 1.4. Определение плат и порта
- `BoardCmbBoxOnChange` (17964): `set ARDUINO_LOCALE=en` + `board list > BoardList.txt`, ожидание `WaitForSingleObject(PID, 5000)`. Разбор — по позициям заголовков колонок Port / Board / FQBN / Core в первой строке. Отсюда и английская локаль: при локализованном выводе заголовки не найдутся.
- Особый случай: порт Bossa с платой Unknown подставляется как `arduino:sam:arduino_due_x`.
- `CheckArduinoComPort` (21384): реестр `HARDWARE\DEVICEMAP\SERIALCOMM`, ищется значение `USBSER000`. `ComPortNmbOnclick` открывает порт объектом `MyPort` (QCOMPORT). Serial monitor в меню есть, ветка обработчика пустая.

### 1.5. Board Manager (форма с 1546, код 20395–21562)
- Данные: `board listall` → `BoardListAllInstalled.txt`, `board search` → `BoardListAllKnown.txt`, `core list` → `CoreListInstall.txt`, `core search` → `AllCoreList.txt` (`RefreshBoardList`, 20762). Запуск через `GetConsoleOutPut` (19264): .bat, окно ожидания с индикатором и кнопкой Stop, ожидание по размеру файла и попытке открыть его на запись.
- Таблицы: установленные платформы + недостающие из полного списка с пометкой «Not installed»; при выборе платформы — список её плат и тексты `boards.txt`, `platform.txt`, `programmers.txt` из `<Arduino15>\packages\<vendor>\hardware\<arch>\<version>\`.
- Фильтр по платформе, кнопки Install core, Select board.
- Пункты меню «Core operations» (Download, Search, Uninstall, Update index, Upgrade) все вызывают `RefreshBoardList` — отдельных действий за ними нет.
- Вкладка Additional URLs: текст хранится в `AdditURLEdit.txt` (11567, 12690); в командах arduino-cli он нигде не используется (по поиску в файле).
- `RunOnClickBoardMng` — копия кода Library Manager (команды `lib ...`).

### 1.6. Library Manager (форма с 2150, код 18364–18611, 19596–19726)
- Источник — `library_index.json` из папки data. Разбор построчный, без JSON-парсера: блоки от `"name"`+`"version"` до `"checksum"` склеиваются в строку и пишутся в `parsedJson.txt`, из него заполняется таблица. Повторный разбор — только после Update Lib Idx.
- Поиск по имени: Enter / стрелки в поле поиска.
- Комбобоксы Type и Topic заполняются, но в фильтрации не участвуют.
- Команды `lib deps / download / examples / install / list / search / uninstall / update-index / upgrade` из списка, вывод в `cli.msg`.

### 1.7. Окно Arduino CLI Help (форма с 2538, код 18184–18300, 19187–19547)
- Список команд верхнего уровня, подкоманды берутся из вывода `<cmd> --help` (раздел «Available Commands:»), список общих флагов, строка команды, запуск с выводом, перекодировка UTF-8 → 1251.

### 1.8. Вкладка Includes для скетчей (15568, 19795–20151)
- Для .ino / .h / .cpp вместо дерева include показывается список `#include` текущего файла (`CreateArdINCList`).
- `GetIncludedLibPath`: если скетч менялся после сборки (`flNeedToVerifyIno=1`), сначала Verify; затем из `<BuildPath>\compile_commands.json` берутся пути .cpp библиотек, реально использованных при сборке. Щелчок по элементу открывает .cpp и .h библиотеки.

### 1.9. Настройки (IDE Options → Arduino, 4264–4600; чтение 11500–11560, запись 12677–12690)
- Поля: Sketchbook, arduino-cli.exe, Build path, Library path, Log file, arduino-cli.yaml, Data path, Downloads path, Arduino15 по умолчанию (`%APPDATA%`), Warnings, Log level, Additional URLs. Хранение — RQdb.ini.
- Вкладка «Cli config file» показывает yaml (перекодировка из UTF-8), вкладка Network пустая.
- `SaveIDEOptions` (17040) при каждом вызове — а он вызывается и перед каждым Verify — выполняет `config init --overwrite` дважды и `config set directories.data / downloads / user`.
- При старте `config dump` → `directories_data$`, `directories_downloads$`, `directories_user$`.

### 1.10. Файлы
- .ino / .h / .cpp / .c сохраняются в UTF-8 (перевод 1251 → UTF-8), при загрузке проверка на буквы 1251 с предупреждением.
- При «Сохранить как» для .ino: если файл лежит не в папке с тем же именем, создаётся папка `<Sketchbook>\<имя>\`.
- Меню: Arduino Examples (папка `<data>\examples`, маска *.ino), Arduino Sketchbook, Preferences.

### 1.11. STM32
- Запуск STM32CubeProgrammer по жёстко заданному пути `C:\Program Files\STMicroelectronics\...`, проверка ST-Link через `STM32_Programmer_CLI.exe -c port=swd mode=UR`, окно справки по загрузчику.

## 3. План переноса

### Принципы
- Команды arduino-cli запускаются через `RunCompiler` (канал), без промежуточных .bat и файлов-маркеров. Для этого у `RunCompiler` нужен параметр кодировки вывода: arduino-cli пишет в UTF-8, а сейчас вывод переводится из OEM (ключ `[Compiler] OemOutput`). Вариант: перечисление `ocOem / ocUtf8 / ocAnsi` вместо Boolean.
- `ARDUINO_LOCALE=en` — через `SetEnvironmentVariable` перед запуском (наследуется дочерним процессом), без setclilocale.bat.
- Каждой команде передаётся `--config-file <CliCfgFile>`. yaml пишется (`config init` / `config set`) только когда в настройках поменялись папки, а не при каждом сохранении настроек и не перед каждой сборкой.
- Код, не связанный с VCL (сборка командных строк, разбор вывода `board list`, `core list`, `compile_commands.json`, строк ошибок gcc), — в отдельный модуль **ArduinoCli.pas**, по образцу ObjParse.pas. Окна — отдельными модулями на Ui*-компонентах.

### Этап 1. Режим Arduino, Verify и Upload
1. **Режим среды.** `FLangMode`: 0 — Delphi, 1 — Basic, 2 — Arduino. Как режим выбирается — раздел 5. `ApplyLangMode`: в режиме Arduino спрятать конструкторы, палитру, кнопки отладчика и Watch, показать ряд Arduino.
2. **Сборка.** В `CompileProject` третья ветка — `CompileArduino`: `compile -b <FQBN> --build-path ... --libraries ... --warnings ... --log-level ... --log-file ... --config-file ... <папка скетча>`. Compile → Verify, Compile & Run → Verify + `--upload --port <порт>`. Флаг `-e` (экспорт .hex/.bin в папку скетча) — настройкой.
3. **Ошибки.** gcc пишет `путь:строка:столбец: error: текст`. В `ParseCompilerLine` добавить разбор этого формата (сейчас только `File(line)`); переход по двойному щелчку уже есть в `LogEditDblClick`. Как именно arduino-cli указывает путь и номер строки для .ino (исходный файл или сгенерированный .ino.cpp) — проверить на реальном выводе с ошибкой, до того как писать разбор.
4. **«Platform not found».** Предложить `core install <packager:arch>` — первые две части FQBN.
5. **Плата и порт — два независимых выбора.**
   - **Плата (FQBN)** — для какой платы собирается скетч. Список — платы установленных платформ (`board listall`; в 0.18.1 эта команда перечисляет платы платформ, которые установлены). Список меняется только после установки / удаления платформ в Board Manager, поэтому читается один раз и хранится в памяти до следующей операции в Board Manager. Выбранный FQBN сохраняется в .prj скетча. Для Verify нужен только FQBN.
   - **Порт** — куда загружать: конкретная плата, физически подключённая к USB. Не хранится, берётся по факту подключения: список портов обновляется по событию Windows о подключении / отключении устройства (раздел 6). Нужен только для Upload.
   - `board list` для выбора не нужен. Разбор вывода arduino-cli — с английской локалью по позициям заголовков, как в 853-8; переход на `--format json` — вместе с JSON-разбором для менеджеров (флаг `--format text|json` в 0.18.1 есть — он перечислен в списке флагов окна CLI Help в 853-8).
6. **Остановка.** Кнопка Program reset в режиме Arduino — `TerminateProcess` для запущенного arduino-cli.
7. **Состояние по вкладкам.** Сборка и загрузка привязаны к вкладке, как задумано для Compile / Run, — чтобы во время загрузки одного скетча можно было работать с другим файлом.

### Этап 2. Файлы скетча
1. Новый проект типа Arduino и «Сохранить как» для .ino: папка с именем скетча в SketchPath (как в 853-8).
2. Кодировка: для .ino / .h / .cpp / .c по умолчанию UTF-8 без BOM при сохранении нового файла; предупреждение, если в файле найдены байты 1251 (механизм определения UTF-8 уже есть).
3. Меню: Examples (`<CliDataPath>\examples` и примеры библиотек), Sketchbook — через существующее окно выбора папки / файлов.

### Этап 3. Вкладка Includes для скетча
1. В режиме Arduino показывать `FTabIncludes` (сейчас только Basic) со списком `#include` текущего файла.
2. После успешной сборки читать `<BuildPath>\compile_commands.json` и сопоставлять каждому `#include` папку библиотеки, реально взятую компилятором (логика `GetIncludedLibPath`). Если скетч изменён после сборки — пометка «не собран», без автоматического запуска Verify.
3. Двойной щелчок — открыть .h и .cpp библиотеки обычным открытием файла во вкладке.

### Этап 4. Board Manager
1. Окно на Ui*-компонентах: установленные платформы, все платформы, платы выбранной платформы, просмотр boards.txt / platform.txt / programmers.txt.
2. Действия, которые в 853-8 стоят заглушками: `core install / uninstall / upgrade / update-index / search` — каждое своей командой, вывод в лог окна.
3. Additional URLs: хранить в `[Compiler.Arduino]` и передавать в CLI (`config set board_manager.additional_urls` в yaml или `--additional-urls` в командах `core`).
4. Данные — из вывода команд (`core list`, `core search`, `board listall`) в памяти, без промежуточных txt-файлов в папке IDE.

### Этап 5. Library Manager
1. Установленные — `lib list`; поиск — `lib search <слово>` вместо разбора всего library_index.json в parsedJson.txt.
2. Фильтры Type и Topic — реально применять (в 853-8 не используются).
3. Действия install / uninstall / upgrade / update-index / examples.
4. Для `--format json` нужен JSON-разбор: в Delphi 7 его нет. Небольшой собственный разбор в ArduinoCli.pas (объекты, массивы, строки, числа) закроет и `board list`, и `core list`, и `lib search`. Делать вместе с этим этапом.

### Этап 6. Serial monitor
В 853-8 пункт меню есть, обработчик пустой. Два варианта:
- `arduino-cli monitor` через канал. Используется arduino-cli **0.18.1** (2021-04-13); команды `monitor` нет в списке команд, который 853-8 показывает для этой версии (board, burn-bootloader, cache, compile, completion, config, core, daemon, debug, help, lib, outdated, sketch, update, upgrade, upload, version). Вариант отпадает, пока CLI не обновлён.
- Собственное чтение порта (CreateFile / ReadFile в потоке). Не зависит от версии CLI — основной вариант.
В обоих случаях перед Upload монитор закрывает порт и после загрузки открывает снова.

### Этап 7. Консоль arduino-cli
Аналог Arduino CLI Help: дерево команд из `--help`, строка команды, запуск через канал, вывод в лог. Низкий приоритет — нужен для команд, которых нет в интерфейсе.

### Этап 8. STM32 и особые платы
1. Путь к STM32CubeProgrammer и STM32_Programmer_CLI — в настройках, вместо жёсткого пути.
2. Проверка ST-Link — командой через канал, вывод в лог.
3. Порт загрузчика Bossa (Due): в 853-8 ищется через WMI-скрипт. В unIDE имя устройства («Bossa Program Port (COMn)») приходит из SetupAPI при перечислении портов (раздел 6); для такого порта с платой Unknown — подстановка `arduino:sam:arduino_due_x`, как в 853-8.

### Настройки
- `[Compiler.Arduino]`: к существующим полям добавить DownloadsPath, Arduino15Path (папка Arduino IDE по умолчанию в `%LOCALAPPDATA%`), Warnings, LogLevel, ExportBinaries, AdditionalUrls, CubeProgrammerPath, SerialBaud.
- Пути — на странице Compilers → Arduino (как сейчас); Warnings, Log level, Additional URLs, просмотр yaml — на пустой вкладке `TabArduino`.
- Флажки с вкладки Arduino в RQdebugger (по снимку окна и ключам RQdb.ini): Show verbose output — Compilation (`ArdCompileDetail`) и Upload (`ArdLoadDetail`), Verify code after upload (`ArdCheckCode`), Save sketch when verifying or uploading (`ArdSaveScetch`). Переносятся в `[Compiler.Arduino]` как CompileVerbose, UploadVerbose, VerifyAfterUpload, SaveBeforeBuild и передаются в команды (`-v`, `--verify` у upload — наличие флагов в 0.18.1 проверить по `compile --help`).
- Импорт из RQdb.ini, раздел `[Arduino]`: кнопка «Импорт из RQdb.ini» на странице Compilers → Arduino и автоматически при первом входе в режим Arduino, если `[Compiler.Arduino]` пуст, а RQdb.ini найден (папка RQdebugger берётся из `[Compiler.RapidQ Basic] IdePath`, иначе — выбор файла). Соответствие ключей:

| RQdb.ini `[Arduino]` | unIDE `[Compiler.Arduino]` |
|---|---|
| sketchbookPathEdit | SketchPath |
| CliPathEdit | CliFile |
| BuildPathEdit | BuildPath |
| ArdLibraryPathEdit | LibPath |
| ArdLogFileEdit | LogFile |
| ArdCliCfgFileEdit | CliCfgFile |
| ArdCliDataPathEdit | CliDataPath |
| ArdCliDOWNLPathEdit | DownloadsPath |
| ArdCompileDetail / ArdLoadDetail | CompileVerbose / UploadVerbose |
| ArdCheckCode / ArdSaveScetch | VerifyAfterUpload / SaveBeforeBuild |
| ArdWarningCmb / ArdLogLevelCmb | Warnings / LogLevel |
| AdditURLEdit.txt (файл рядом с RQdb.ini) | AdditionalUrls |

  Особенности при импорте:
  - в присланном разделе `ArdWarningCmb=0` и `ArdLogLevelCmb=0` — это не допустимые значения (`none/default/more/all`, `trace...panic`); если в ключе не одно из них — ставить `none` и `info`;
  - `LibraryPathEdit` в 853-8 не читается (используется `ArdLibraryPathEdit`) — не переносится;
  - `ArdCompilerMsg` и `ArdBoardMngLinks` — какому элементу окна они соответствуют, по коду 853-8 не определено; уточнить по 854-0;
  - в списке Additional Boards Manager URLs на снимке, кроме адресов `package_*.json`, есть две строки-папки (`...\sketchbook\libraries`); в `board_manager.additional_urls` передавать только строки, начинающиеся с `http`.

## 4. Решения (2026-10-05)
1. COM-порт не хранится: берётся по факту подключения платы (виртуальный порт зависит от разъёма USB и других условий). Список портов обновляется по событию Windows WM_DEVICECHANGE — раздел 6.
2. Версия arduino-cli: 0.18.1 (alpha, commit b3cf8e19, 2021-04-13). Команды `monitor` в ней нет — Serial monitor делается своим чтением порта.

## 5. Переключение в режим Arduino

В unIDE режимов три (Delphi, Basic, Arduino), а не два, как в RQdebugger. Сейчас Delphi / Basic выбирается автоматически по активному файлу и проекту (`IdeBasicMode`, `ApplyLangMode`) при смене вкладки.

### Предлагаемый вариант: автоматически по файлу + переключатель для спорных случаев
- В группе `grpCompiler` (ряд Project) слева — переключатель режима **Delphi / Basic / Arduino** (`TUiComboBox` или три `TUiRadioButton`, как Basic/Arduino в RQdebugger). Он показывает текущий режим и позволяет сменить его вручную.
- Автоматический выбор при переходе на вкладку:
  - `.ino`, `.pde` → Arduino;
  - `.bas`, `.inc`, `.bi` → Basic; `.pas`, `.dpr`, `.dfm`, `.dpk` → Delphi (как сейчас);
  - `.h`, `.c`, `.cpp` → Arduino, если открыт проект типа Arduino или в той же папке есть `.ino` с именем папки (скетч); иначе режим не меняется.
- Ручной выбор запоминается за вкладкой (поле в записи окна `FWindows`, рядом с `IncOwner`) и действует, пока вкладка открыта. Для файла проекта — пишется в .prj, чтобы .h/.cpp скетча открывались сразу в режиме Arduino.
- **Вход в режим Arduino** (из любого другого режима, не при каждой смене вкладки внутри Arduino): перечисление портов (раздел 6). Дальше список портов обновляется сам по событиям подключения / отключения; кнопка «Обновить» остаётся на случай, если событие не пришло. Список плат (FQBN) при этом не трогается — он зависит только от установленных платформ.
- Выход из режима Arduino: если открыт Serial monitor — порт закрывается.

### Что меняется в коде
- `IdeBasicMode: Boolean` → `IdeLangModeFor(AWinIdx): Integer` (ручной выбор вкладки, иначе правило по расширению и проекту).
- `ApplyLangMode`: три набора видимости; в Arduino — Verify, Upload, выбор платы (FQBN), выбор порта, Tools (Board manager, Library manager, Serial monitor); спрятаны кнопки отладчика, Watch, палитра, конструкторы, вкладка Code; вкладка Includes — в варианте для скетча (этап 3).
- `CompileProject`: ветка по `FLangMode`, а не по `BuildIsRapidQ`.
- Событие «вошли в режим Arduino» — в `ApplyLangMode` при смене `FLangMode` на 2.

### Альтернатива: только ручной переключатель, как в RQdebugger
Режим меняется только переключателем, при смене вкладки — нет. Проще, но при работе одновременно с .bas и .ino режим нужно переключать руками при каждом переходе между ними, иначе Compile соберёт не тем компилятором.

## 6. Определение порта по событию подключения платы

### Что сейчас в RQdebugger
- `ArdBasTabChange`: VBS-скрипт через WMI (`SELECT * FROM Win32_SerialPort`), запуск `cscript`, ожидание `sleep 1`, разбор `serialList.txt`. Работает только в момент переключения на Arduino; подключение платы позже не видно.
- `CheckArduinoComPort`: реестр `HARDWARE\DEVICEMAP\SERIALCOMM`, поиск значения `USBSER000`. Номер есть, имени устройства нет.

### Как сделать в unIDE
Отдельный модуль **ArduinoPorts.pas** (без форм):

1. **Событие.** Скрытое окно модуля (`AllocateHWnd`) получает `WM_DEVICECHANGE`:
   - `DBT_DEVICEARRIVAL` — устройство подключено;
   - `DBT_DEVICEREMOVECOMPLETE` — отключено;
   - в `lParam` заголовок `DEV_BROADCAST_HDR`; при `dbch_devicetype = DBT_DEVTYP_PORT` это `DEV_BROADCAST_PORT` с именем порта (`COM5`);
   - дополнительно `RegisterDeviceNotification` на интерфейс `GUID_DEVINTERFACE_COMPORT` ({86E0D1E0-8089-11D0-9CE4-08003E301F73}) — тогда приходят и `DBT_DEVTYP_DEVICEINTERFACE`. Не все драйверы виртуальных портов рассылают `DBT_DEVTYP_PORT`; подписка на интерфейс эту разницу закрывает. Какие сообщения реально приходят от ваших плат (Due, STM, CH340 и т.п.) — проверить по логу на первом запуске.
   - `DBT_DEVNODES_CHANGED` — запасной сигнал «что-то поменялось в диспетчере устройств».
   Это тот же механизм, по которому обновляется Диспетчер устройств.
2. **Перечисление.** По событию — не сразу, а через таймер ~300–500 мс (при подключении событий приходит несколько подряд): SetupAPI, класс портов `GUID_DEVCLASS_PORTS`, `SetupDiGetClassDevs` / `SetupDiEnumDeviceInfo`, для каждого устройства:
   - `SPDRP_FRIENDLYNAME` — «Arduino Due Programming Port (COM5)», «Bossa Program Port (COM19)», «STMicroelectronics Virtual COM Port (COM7)»;
   - `SPDRP_HARDWAREID` — `USB\VID_2341&PID_003D...` (VID/PID);
   - имя порта — значение `PortName` из ключа устройства (`SetupDiOpenDevRegKey`).
   Вызовы быстрые, без внешних процессов, VBS и временных файлов. Delphi 7 заголовков SetupAPI не содержит — нужные функции объявить в модуле самим (`setupapi.dll`).
3. **Сравнение со старым списком** → события модуля `OnPortArrived(PortName, FriendlyName, VidPid)` и `OnPortRemoved(PortName)`.
4. **В Unit1** (только в режиме Arduino):
   - порт появился — добавить в список портов, сделать текущим, если текущего нет; выбранная плата (FQBN) не меняется;
   - порт пропал — убрать из списка портов; если это был текущий — надпись «порт отключён», Upload недоступен, Verify доступен;
   - в логе — строка «Подключено: COM5 — Arduino Due Programming Port» / «Отключено: COM5».
5. **Во время Upload события не применять к выбору порта.** У Due, Leonardo и подобных загрузка начинается со сброса через открытие порта на 1200 бод: плата переподключается, порт исчезает и появляется (у Due — как Bossa Program Port). arduino-cli это обрабатывает сам; если IDE в этот момент поменяет текущий порт, следующая загрузка уйдёт не туда. После окончания Upload — одно перечисление и обновление списка.
6. **Serial monitor:** порт пропал — монитор закрывает его и пишет об этом; порт вернулся с тем же именем — предлагает открыть снова.

### Порядок
Модуль ArduinoPorts.pas делается первым шагом этапа 1: проверяется отдельно (лог событий и списка портов при подключении / отключении плат) до того, как к нему будут привязаны Verify и Upload.
