# RqLcl / RqToFb: что из документации RapidQ не сделано (2026-10-08)

Составлено на коммите b74124d ветки RQFreeBasic, обновлено после 34d60b8 (QCANVAS, QBITMAP, QSCROLLBAR, QTRACKBAR, QSCROLLBOX, QOVALBTN, QOUTLINE, QHEADER, Printer, QSOCKET, QNOTIFYICONDATA, рисование на QFORM), 9572113 (событие WndProc), ede0410 (BIND, CALLFUNC, CODEPTR), 199a5ae (имена параметров из DECLARE), 28f8288 (раздел 2 — недостающие члены сделанных классов) и коммита 2026-10-08 с VARPTR, MEMCPY, SENDMESSAGE, SHELL, QUICKSORT (раздел 3). Как проверялось:
- свойства, методы и события со страниц классов (`rapidq_ref/html_doc/q*.html`) сравнены с объявлениями в `RqLcl/inc/*.bi`;
- функции и операторы из «Other reserved keywords» (otherdetail.html) и консольного приложения (consoledetail.html) прогнаны через препроцессор и fbc 1.10.1 (Wine, win32);
- директивы — по главе 3.

Пометка **(RQ)** — встречается в RQdebugger844-40.bas или в его include. Отмечать сделанное: `[x]`.

Запись TYPE (найдено при WriteUDT): тест пользователя в RapidQ 2026-10-08 — `S AS STRING*5`, `N AS INTEGER` → SIZEOF 9; `"ab"` → `[ab   ]` (байты 97 98 32 32 32), `"1234567"` → `[12345]`. Сделано: d6b515f — `Type … Field = 1` (поля без выравнивания), 1b81d7d — поле `STRING*N` ровно N байт (массив байт и свойство с тем же именем; пробелы при записи, обрезка до N). Не работает с таким полем: VARPTR поля, `MID$(поле, …) = …`. В документации (html_doc / rapidq.chm) о выравнивании прямо не сказано.

- [x] Событие `WndProc` у QFORM, QEDIT, QLISTBOX, QLABEL (9572113): подмена оконной процедуры окна элемента в DLL (`dll/rqlclwnd.pas`), обработчик вызывается до LCL и получает все сообщения окна, включая WM_COPYDATA и WM_USER+; у QLABEL — сообщения LCL, Hwnd — окно родителя (как у RapidQ — не проверено). В RQdebugger и его include событие `WndProc =` встречается только в закомментированных строках; подмена окон там — через `NewWndProc.Inc` (пункт BIND / CODEPTR ниже).

CopyMode теперь — номер RapidQ (cmBlackness 0 … cmWhiteness 14), переводится в код LCL; раньше у QIMAGE передавался как есть.

Полностью по документации: QCHECKBOX, QDIRTREE, QFILELISTBOX, QFONT, QFONTDIALOG, QGAUGE, QGROUPBOX, QLISTVIEW, QMAINMENU, QMENUITEM, QRADIOBUTTON, QREGISTRY, QSPLITTER, QSTATUSBAR, QSTRINGLIST, QTABCONTROL, QTIMER, QOPENDIALOG, QSAVEDIALOG, QSCROLLBAR, QTRACKBAR.

## 3. Функции и операторы

Сделано 2026-10-08 (rqrt.bi, RqToFb.pas; тесты `tofb/tests/memfuncs.bas`, `memrec.bas` — Smart 32 и 64 бит, Compat 32 бит):
- [x] MEMCPY (RQ), MEMSET, MEMCMP — `RqMemCpy`/`RqMemSet`/`RqMemCmp`, со скобками и без. Переменная-запись (TYPE без EXTENDS), её элемент массива или поле-запись своего компонента параметром — её адрес: так в rapidq2.inc (`MEMCPY(gRQ2_MeasureItem, lParam, …)`, `MEMSET(DevM, 0, …)`) и RapidFRM.inc (`MEMSET(This.CC, …)`) — вывод из кода, в RapidQ не проверялось. MEMCMP при совпадении — 1 (документация: «не 0»). Нулевой адрес: Smart — предупреждение, Compat — ошибка.
- [x] VARPTR в `&`-переменную (RQ, около 25 мест), VARPTR$ (RQ) — `RqVarPtr(@x)`: у строки — адрес символов (через него пишут в строку QFileDialog.inc и conversion.inc), у остального — адрес; `VARPTR$(адрес)` — строка по адресу до нулевого байта. Только 32 бит: в 64 бит адрес в LONG не помещается.
- [x] SENDMESSAGE (RQ), POSTMESSAGE, KILLMESSAGE — оператор и функция; функции Windows через DyLibSymbol (не спорят с DECLARE программы); строка в lParam — адрес её символов (как у RapidQ — не проверено); свой `DECLARE … SendMessage LIB` программы не трогается.
- [x] SHELL(команда, режим) с двумя параметрами (RQ) — CreateProcessA с этим режимом, не ждёт, результат — номер процесса. Не запустилась (`SHELL("Start "+helppath$, 0)` в RQSV105b2023-13Inc-4.inc: Start — команда cmd) — в Smart ещё раз через `cmd /c`, в Compat — 0; что делает RapidQ — не проверено. `SHELL команда` — как раньше, Shell FreeBASIC (ждёт).
- [x] QUICKSORT (RQ) — все числовые типы и STRING, многомерный массив, часть массива; ASCEND → 0, DESCEND → 1 (в include не объявлены — слова RapidQ). «Span sort» через два массива — ошибка перевода: в FreeBASIC массивы не лежат подряд.
- [x] SIZEOF(INTEGER), SIZEOF(WORD), SIZEOF(DWORD) и др. — тип FreeBASIC (`SIZEOF(Long)`). Раньше оставались как есть: в 64 бит SIZEOF(INTEGER) давал 8 вместо 4 (нашлось на тесте MEMCPY), WORD/DWORD fbc не знает.
- ~~ROUND(x, n) с двумя параметрами~~ — ошибка в прежнем списке: у ROUND по документации один параметр, `ROUND(x, n)` нет ни в документации, ни в исходниках rapidq_ref (проверено 2026-10-08). ROUND(x) был в rqrt.bi и раньше.
- [x] CODEPTR / CALLBACK (RQ), BIND (RQ), CALLFUNC (RQ) — ede0410: `CODEPTR(P)` → `Cast(Integer, @P)`, `BIND v TO P` → `v = Cast(Integer, @P)` + шаблон, `CALLFUNC(v, …)` → вызов по указателю с параметрами шаблона. Переходники RapidQ с машинным кодом x86 (`SetNewWndProc` в NewWndProc.Inc, `SetNewCallBack_0…8`, `SetNewFwToCallBack`) заменяются: процедура FreeBASIC сама годится как оконная процедура, `SetNewWndProc` = SetWindowLong(окно, GWL_WNDPROC, адрес). Только 32 бит. Не сделано: метод своего компонента в BIND/CODEPTR (rapidq2.inc: `BIND This.BindIndex TO This.WindowProc`, `CODEPTR(This.EnumChild)`) — ошибка перевода. Подробно — RAPIDQ_RULES.md, «Указатели на процедуры».

Сделано 2026-10-08, второй коммит (тест `tofb/tests/variant.bas`):
- [x] FORMAT$ — `RqFormat`, Format Delphi: индекс `%0:d`, `-`, ширина, точность, `*`, типы d u x p e f g n m s, `%%`; e/f/g/n — правила STRF$; m — как n, без знака валюты; разделители — точка и запятая между тысячами (у Delphi/RapidQ — из настроек Windows, не проверено). Неверный формат или тип значения: Compat — ошибка, Smart — предупреждение.
- [x] INITARRAY — `RqInitArray(Массив(), …)`: первые элементы по порядку в памяти, многомерный массив — весь блок; числовые типы, STRING, VARIANT. Лишние значения не пишутся (Smart — предупреждение).
- [x] VARTYPE и тип VARIANT — `RqVariant`: число / дробное / строка, VARTYPE 0/1/2; в операции вид выбирает левый операнд (примеры datatypes.html дают 200.5 и 10199.5); параметр VARIANT — по ссылке. Всё, чего нет в примерах документации (другие операции, сравнения, VARIANT в LONG/STRING через Val/Str, PRINT без 9 знаков), — по тому же правилу, с RapidQ не сверялось.
- [x] `=>` и `=<` как `>=` и `<=` (QSpinEdit.inc; в operators.html их нет).

Собирается, но результат, вероятно, другой:
- [ ] RGB — по документации RapidQ возвращает BGR (цвет Windows), RGB FreeBASIC — `&HFFRRGGBB`: `RGB(255, 0, 0)` должен давать `&HFF`, сейчас `&HFFFF0000`. В RQdebugger RGB не встречается.
- [ ] INT(x) при rapidq.inc: там `$define int integer`, препроцессор делает из `INT(2.7)` `integer(2.7)` — ошибка fbc. Как RapidQ применяет этот $define к функции INT — не проверено (нужен тест в RapidQ).

## 4. Язык и директивы

- [ ] `$MACRO`
- [ ] `$OPTION DECIMAL`, `ICON`, `INKEY$`, `WEAKTYPE`, `BYTECODE`, `VBDLL` (`GTK` — только Linux)
- [x] тип VARIANT (RQ — одно место: `FUNCTION CByteNum … AS VARIANT` в conversion.inc) — см. раздел 3
- [ ] передача по ссылке через `@` при вызове (сейчас — предупреждение, параметр получает копию)
- [ ] шаблоны `TYPE Имя<Тип>`
- [ ] числовые метки, `ON … GOSUB`, `RETURN метка`
- [ ] CREATE внутри SUB
- [ ] `STATIC Имя` без `AS` (встречается в RQFormDsg2026-7.bas; fbc: «Default types or suffixes are only valid in -lang deprecated»)
- [x] Имена параметров в DECLARE и в заголовке SUB/FUNCTION разные (199a5ae). Тест пользователя 2026-10-08: `DECLARE SUB T (A AS LONG)`, `SUB T (B AS LONG)`, `PRINT A, B`, `T 5` → `50`, то есть A = 5, B = 0: в теле действуют имена из DECLARE, имя из заголовка — необъявленная переменная. Препроцессор делает так же, с предупреждением. Встречается: CallBack_2.Inc (`hFunction` / `cbIndex`); RQSV105b2023-13Inc-4.inc и RQdebugger — `FileNameParse$` (`cFileName` / `FileName$`), `StrCrp`, `CrpStr1`, `CrpStr` (`key` / `keys`), `ListGridDrawCell` (`R` / `Rect`; там первой строкой `exit sub ' почему-то выскакивает ошибка !!!`).
- `CASE > 5` без IS — ошибка перевода: в RapidQ это не сравнение (тест 2026-10-08), смысл не выяснен; по документации сравнение — `CASE IS > 5`.
