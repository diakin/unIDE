# SyntaxHLClaude — сводка работы на 26.09.2026

Темы оформления (свои элементы Ui*), своё меню и диалоги, палитра и сборка проектов пользователя, мастер меню конструктора форм, разбор «Перенести в .dfm».

## 1. Общие правила

- Delphi 7, сборка dcc32, Windows 7.
- Исходники отдаются в CP1251 с CRLF.
- В новом коде переменные называются по смыслу. Однобуквенные в старых модулях пока не переименовываются: это отдельный шаг после отладки тем.
- Стиль ответов: спокойно, без маркетингового тона. Не возвращать пользователю его же гипотезу как подтверждённую; причину называть только проверенную по коду, логу или файлу.
- Меняется только то, о чём просили. Файлы отдаются целиком, с перечнем изменений.

## 4. TUiTheme (невидимый компонент для программ пользователя)

- Свойства: `Kind`, `CustomColors` (строки «Роль=цвет»), `FormColors` (красить фон и шрифт форм; меняются только clBtnFace/clWindowText и прошлые цвета темы), `AutoSave` (по умолчанию True), `IniFile` (пусто — «программа.ini» рядом с программой), `IniSection` (по умолчанию UiTheme; цвета — раздел «UiTheme.Colors»), `OnChange`.
- Методы: `RoleColor`, `SetRoleColor`, `LoadColors`/`SaveColors`, `SaveSettings`/`RestoreSettings`, `IniFileName`.
- В программе ставит тему всей программе, подключается к `Screen.OnActiveFormChange` (вызывает прежний обработчик).
- В IDE `UiThemeHostLocked := True` (initialization Unit1): TUiTheme на форме в конструкторе красит только элементы своей формы, общую тему не трогает, ini не читает и не пишет.
- Руководство пользователя по UiTheme — отдельный документ (Claude Docs и файл «UiTheme - руководство.md»).

## 6. Своё меню (UiMenus)

- `TUiMenuBar`: строка меню по пунктам TMainMenu. В Dark/Custom у окна `Menu = nil` и видна строка; в Light строка скрыта, у окна меню Windows. Переключается сама по `UM_UITHEMECHANGED`. Перехватывает у окна `WM_SYSCOMMAND`/`SC_KEYMENU` (Alt, F10, Alt+буква) и `OnShortCut` (горячие клавиши пунктов).
- Выпадающие окна (`TUiMenuWindow`), свой цикл сообщений (`UiTrackMenu`): мышь, стрелки, Home/End, Enter, Esc, буква из &, переход по пунктам строки. OnClick пункта с подменю — перед раскрытием. Значки: ImageIndex (SubMenuImages владельца или Images меню) и Bitmap; отмеченный со значком — рамка.
- `TUiPopupMenu`: в Dark/Custom своё окно, в Light — меню Windows.
- `TUiMainMenu`: в работающей программе сам создаёт окну TUiMenuBar.
- В IDE: `FMenuBar` по MainMenu1; всплывающие меню IDE (вкладки, редактор, конструктор, логи, FSchemaMenu в Unit2) — TUiPopupMenu.
- Не поддерживается: OwnerDraw, колонки (Break). Одиночный Alt сразу открывает первое меню.

## 7. Диалоги цвета и шрифта (UiStdDlgs)

- `TUiColorDialog`: 48 основных цветов, 16 своих (CustomColors в формате TColorDialog), поле оттенок/насыщенность, полоса яркости, R/G/B, RRGGBB, образец «было/стало».
- `TUiFontDialog`: список шрифтов с поиском, начертание, размер, fdEffects (зачёркнутый, подчёркнутый, цвет), fdFixedPitchOnly, fdLimitSize, fdApplyButton/OnApply, образец.
- В Light — диалоги Windows. В IDE: ColorDlg и FontDlg в Unit2.

- Контекстное меню конструктора → Menu: Insert, Delete, Create Submenu (по пункту, выбранному в дереве Objects), Select Menu..., Edit Menu..., Save As Template..., Insert From Template..., Delete Templates..., Insert From Resource... (.rc, MENU/MENUEX).
- Окно не закрывается после вставки; вторая кнопка «Выйти», после вставок/правок — «Отмена» (жирная, оранжевая), откатывает все действия окна (по шагу отката конструктора на каждое).

- В конце списка — меню самой формы «(в форме)»: пункты с именами из .dfm; правка подписи и клавиши, снятие, новые пункты («Пункт перед», «Подменю», «Удалить пункт»); кнопка «Применить» (DsgMenuWizardApply, новые пункты — DsgMenuInsertNew); «Удалить» — меню целиком с подтверждением.
- Главное меню у формы одно: при вставке TMainMenu прежние TMainMenu/TUiMainMenu удаляются тем же шагом; кнопка «Добавить» становится «Заменить».

- Имена пунктов по подписи (New1, Open1, N1), без обработчиков (как в Delphi).

## 11. «Перенести в .dfm» (DfmMove.pas + Unit1) — в работе

- Кнопка на вкладке Objects правее Hide form (`FObjMoveBtn`, `ObjMoveClick`).
- Сейчас только разбор, без переноса. `DfmMoveAnalyze(Дерево, текст .pas, класс формы, список)`, окно `DfmMoveShowReport(список, модуль, ObjMoveGoLine)` — немодальное, поверх остальных.
- Вердикты: «в .dfm» (серым), «целиком», «частично», «нет» с причиной.
- Переносится: поле формы; одна строка `X := TКласс.Create(Self)` на верхнем уровне тела; процедура — FormCreate или вызывается в одном месте и не обработчик; родитель — форма или переносимый. В .dfm уходят Parent, свойства-константы, SetBounds с числами, события на методы формы (их — в published). Вычисляемые значения и вызовы методов остаются («частично»).
- «Нет»: помощники (MakeBtn и т. п.), цикл, if/try/with, несколько мест создания, владелец не Self, локальная переменная, процедура-обработчик или вызывается несколько раз, родитель не переносится. Отдельное окно (TForm, создаётся кодом, например FProgForm) и его компоненты — «переносится в свою форму с .dfm, не в эту».
- Щелчок по компоненту — редактор на строку создания; щелчок по «N: …» в подробностях — на строку N. «Сохранить...» — весь разбор в `<модуль>_dfm_analysis.txt`.
- Нужная правка в Unit1 (`ObjMoveClick`): передавать полный путь — `DfmMoveShowReport(List, PasFile, ObjMoveGoLine)` вместо `ExtractFileName(PasFile)`; тогда диалог сохранения открывается рядом с модулем.
- Следующие шаги: 1) проверить разбор по файлу `*_dfm_analysis.txt` на Unit1 IDE и проекте пользователя; 2) сам перенос (один шаг отката .dfm+.pas, опция «закомментировать вместо удаления»); 3) разбор помощников (MakeBtn, MakeCmpButton — TFactoryRec в ObjParse); 4) перенос постоянной части IDE в .dfm, динамические меню (Reopen, Windows, Projects, Bookmarks, LastBM) оставить в коде.
