## Этап 1 — сделано и подтверждено
Модуль RqDbgInstr.pas (без VCL, в SyntaxHLClaude.dpr):
- Копия `<имя>_rqdbg.bas` рядом с главным .bas; перед каждым оператором проверка точки. Префикс имён RqDbg, при совпадении с исходником (и текстом условий) — UniDbg и др.
- Уровень вызова: в начале SUB `DIM RqDbgLvl`, глубина+1; перед END SUB/EXIT SUB — глубина = RqDbgLvl - 1.
- Код отладчика — после начальных директив; свои массивы заполняет явно.
- Файл команды: `m режим` (0 Run, 1 Into, 2 Over, 3 RunTo), `r точка`, `b точка` (без условия), `c точка` (с условием), `k N` (условие Watch N включено), `#end`. События `<base>_S`/`<base>_G`.
- Пропускается: CREATE/TYPE, объявления, директивы, ELSE/CASE/LOOP/NEXT/WEND/END IF, до первого CASE; однострочный IF — один оператор; строки с `_` — как есть; несобираемые блоки условной сборки.
- Карта строк копии → исходник для ошибок компиляции.

Unit1.pas:
- RapidQ под отладчиком (RqDbgWantedFor): точка останова в главном .bas этой программы или в любом её $INCLUDE-файле (с вложенными), или F7/F8/F4. У Delphi — прежнее правило DbgWanted.

## Выражения в Watch (5ad1f30, подтверждено)
RqDbgInstr:
- Build(..., AWatch) — выражения окна Watch на момент сборки (FWatchExprs). WatchIndex, WatchWhere ("SUB A, SUB B" / "*"), WatchNote, WatchOfCopy, WatchExpr.
- Предварительный проход собирает все глобальные имена общего текста (GlobalAll). В SUB — ProcAll (параметры и все DIM).
- ExprNames: имена выражения без свойств после ".", встроенных функций, чисел; ":" или "'" вне кавычек — не вставляется (RqDbgExprInsertable — та же проверка).
- Размещение: в блок дампа SUB, если все имена известны и хотя бы одно — этой SUB; иначе в RqDbgGlobals, если все имена глобальные.
- Код: элемент массива простого типа — через STR$ или как есть; остальное — через VARIANT (`RqDbgWV`, `RqDbgWT = RqDbgWS + RqDbgWV`). На rc.exe у пользователя работает.
- RqDbgBusy: пока идёт остановка, RqDbg сразу выходит.

Unit1:
- RqDbgBuild передаёт FWatchList; в лог — невставленные выражения с причиной. RqDbgWatchValue — значение или пояснение. Ошибка rc.exe в строке выражения — с текстом выражения.

## Условия в окне Watch (7cfa50a, не проверено)
Пользователь выбрал вариант «условие для точек»: условие строки Watch действует на точки останова. Вариант «остановка по данным в любом месте» (с галкой: в любом месте / только на точке) отложен; пользователь назвал его тоже полезным (значение может меняться по таймеру).

DlgWatch: столбцы Выражение 140, Значение 230, **Условие 80**, Тип 90; ClientWidth 560; пункт меню miWatchCond «Условие...».

RqDbgInstr:
- ClearWatchConditions / SetWatchCondition(выражение, условие) перед Build. RqDbgWatchCondValid: условие начинается со сравнения (=, <>, <, >, <=, >=), дальше не пусто, без ":" и "'".
- Условие выражения N проверяется там же, где вычисляется выражение Watch: в блоке дампа SUB (WatchFits(N, ProcAll)) и в SUB RqDbgWatchCond в конце копии (только глобальные имена) — её зовёт каждый блок дампа и RqDbg для главной части/SUBI. Код: `IF RqDbgWOn(N) THEN / RqDbgCondT = 0 / IF (выражение) условие THEN RqDbgCondT = 1 / IF RqDbgCondT = 0 THEN RqDbgCondOk = 0 / END IF`.
- RqDbg: RqDbgCondReq = 1, если стоп по точке останова (Run; RunTo не на своей точке; Over — когда шаг сам бы не встал, RqDbgStep = 0); Into — никогда. Без условий в копии — `RqDbgCondReq = 0` сразу. При CondReq файл состояния открывается только после проверки условий. Блок дампа: `IF RqDbgCondReq THEN RqDbgCondOk = 1 / условия SUB / RqDbgWatchCond / IF RqDbgCondOk = 0 THEN RqDbgWant = 0 / RqDbgBusy = 0 / RETURN / END IF / RqDbgOpenState / END IF`. **RETURN внутри блочного IF — на rc.exe не проверено.**
- `k N` → RqDbgWOn(N) = 1 (сбрасываются при каждом чтении команды).
- WatchCondition(N), WatchCondWhere (SUB или "*"), WatchCondNote, WatchCondOfCopy (FCopyCond < 0: -(N+1)).
- Регрессия: без условий тело копий 14 образцов не меняется, отличается только рантайм.

## Известные ограничения
- Include без точек и без вкладки с пометкой идёт как есть: F7 в его SUB не заходит. Точка в новом include, поставленная во время сеанса, — серая до пересборки.
- Условие точки или Watch, заданное или изменённое во время сеанса, действует после пересборки; снятие — сразу.
- Условие Watch с локальными именами в SUBI не проверяется (у SUBI нет блока дампа).
- Условие строки "FOR ...: ... : NEXT" вычисляется у первого оператора строки.
- Точки, условия и список Watch между запусками unIDE не сохраняются.
- Если файл впервые встречается в несобираемом блоке условной сборки, а второй раз — в собираемом, вставка будет только в первом месте.
- Нет паузы. Если программа после закрытия unIDE дойдёт до точки, она будет ждать вечно.
- QXpTheme.INC при первом запуске перезапускает exe — не проверялось.
- Глобальная в $IFNDEF-блоке, который на деле не собирается, — ссылка на неё в RqDbgGlobals.
- Пометку главного файла на вкладке убрать нельзя (только закрыть вкладку).

## Проверено прогонами (RapidQ, у пользователя)
- DIM массива в RapidQ не обнуляет его. Простые переменные после DIM — 0.
- Тест 1: GOSUB на метку в SUB работает; метки общие на программу.
- Тест 2: события работают, остановка блокирует программу, Continue возобновляет.
- rc.exe не принимает `FUNCTION Имя AS STRING` без скобок. STR$ даёт число без ведущего пробела.
- Выражения через VARIANT вычисляются (Watch: `SumIdx * 2`, `LimitVal + TotalVal`).
- Открытые вопросы: сохраняют ли локальные SUB значение между вызовами; отсекает ли rc.exe повторный $INCLUDE сам; RETURN внутри блочного IF.
