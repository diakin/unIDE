# Передача в новый чат: unIDE, 2026-10-07 — следующая тема: поддержка FreeBASIC

Репозиторий github.com/diakin/unIDE, ветка RapidQ (коммитить и пушить прямо в неё; перед push — fetch + rebase, пользователь пушит и сам). Последний коммит на момент передачи — 2f41bc9.

Исходники в рабочей копии — CP1251 + CRLF. В репозитории `.gitattributes` с `working-tree-encoding=windows-1251` для .pas/.dfm/.dpr/.inc/.bas/.ini/.clr/.bat/.dof/.prj: блобы в git хранятся в UTF-8 + LF, `git diff` показывает UTF-8. Для правки удобно: копия `iconv -f cp1251 -t utf-8 | tr -d '\r'`, правка, обратно `iconv -f utf-8 -t cp1251 | sed 's/$/\r/'` (без потерь). Проверка синтаксиса — FPC (`fp-compiler`, `fp-units-win-base`, `-Twin64 -Mdelphi`) в модуле-обвязке с заглушками VCL. Пользователь — Windows 7, Delphi 7.

Предыдущие передачи: claude/Передача_в_новый_чат_unIDE_2026-10-06.md; Arduino — claude/Ардуино_разбор_и_план_unIDE_2026-10-05.md и claude/Ардуино_сборка_unIDE_2026-10-06.md.

## Сделано 6–7 октября

### Arduino (проверено у пользователя: скетч компилируется и загружается в плату)
- `CompileArduino(AUpload, AKeepLog)`: `arduino-cli compile` папки скетча, загрузка `-u -p <порт>`. Ключи из IDE Options - Arduino (`ArdLoadBuildOptions`). Ошибки gcc — `ArdParseGccLine` в `ParseCompilerLine` (проверяется первой), `ArdIsGccError` в `IsCompilerError`. Platform not found → `core install` → сборка снова. Program reset снимает arduino-cli.
- Ряд Project в режиме Arduino: кнопки Verify, Upload, Program reset (`btnArdVerify`, `btnArdUpload` в Unit1.dfm, значки 15 и 16 ленты, icons/make_icons.py).
- Список плат на USB `cmbArdPort` (Unit1.dfm, рамка Project): пункт — порт, имя устройства из Диспетчера устройств, FQBN (у выбранного — текущий FQBN, у остальных — по VID/PID из boards.txt). Выбор ставит порт и FQBN (`ArdBoardFromPort`: boards.txt, иначе `arduino-cli board list`). Подпись цели над списками в режиме Arduino спрятана.
- Порты — `TArdPortWatcher` (ArduinoPorts.pas): `WM_DEVICECHANGE` + `RegisterDeviceNotification` (GUID_DEVINTERFACE_COMPORT), перечитывание через 400 мс (SetupAPI, класс Ports, + SERIALCOMM), сравнение списков. Во время загрузки выбор порта не меняется; Serial Monitor закрывает порт на время загрузки (`PauseForUpload`).
- Плата скетча: папка скетча — папка проекта → `[Project.<имя>] Fqbn, BoardName`, иначе `[Compiler.Arduino]`.

### Прочее
- Правая панель: разделитель тянет линию-след (PATINVERT), ширина — при отпускании, затем полная перерисовка (`ApplyRightPanelWidth`). Пользователь: «стало нормально». Остальные два сплиттера и так ставят размер при отпускании.
- Переключатель сборщика `cmbBuildKind`: ручной выбор — «» вручную, …» в подписи, строка в HiLite log, фокус обратно в редактор. Пользователь подтвердил, что FreeBASIC на .dfm был выбран вручную; дальше ничего не нужно.
- **Пробная сборка самого редактора** (коммит 2f41bc9, у пользователя не проверено): проект редактора собирается в `Output\_newbuild\`, переносится как `SyntaxHLClaude_new.exe` (+ .map); Run запускает его (`DelphiRunExeOf`); пробный exe после первого простого (`FStartupDone` в AppIdle) при обычном закрытии делает себя рабочим (`OwnPromoteTrial`: рабочий → .exe.old, _new → .exe). Проект редактора узнаётся по `OwnExeBase` (имя exe без `_new`). Build Release редактора берёт рабочий exe.

## FreeBASIC — что уже есть

- Сборщик `bkFreeBasic = 2` в `CurBuildKind`: .bas — по тексту (`BasDialectOfText`: #-директивы → FreeBASIC, $-директивы и `AS QFORM` → RapidQ, перевес; поровну — тип проекта, иначе RapidQ); .bi без IncOwner → FreeBASIC; .inc/.bi с IncOwner — по главному файлу; ручной выбор в `cmbBuildKind`.
- `CompileProject`: для bkFreeBasic пишет в лог «Сборка FreeBASIC здесь пока не подключена» — место для `CompileFreeBasic`.
- `BuildTargetOf(bkFreeBasic)` — пока просто файл вкладки, если .bas («главный файл по #include — вместе со сборкой FreeBASIC»).
- `ApplyLangMode`: для FreeBASIC спрятаны кнопки шагов отладчика и вкладка Includes; Compile & Run виден.
- `RunTarget`: для сборщиков, кроме Delphi и RapidQ, пишет «здесь пока не подключён».
- Тип проекта FreeBASIC (`ProjectBuildKind`, `ProjectTypeOf`).
- IDE Options - Compilers - FreeBASIC (Unit2, ~3617): поля `FBCompPath` (FB compiler), `IncPath`, `LibPath`.
- Схемы подсветки `schemes/fb.clr`, `schemes/bi.clr`.

## FreeBASIC — что решено пользователем раньше (память)

- unIDE работает с четырьмя компиляторами (Delphi, RapidQ, FreeBASIC, arduino-cli), вкладки всех типов открыты одновременно; сборщик решает файл активной вкладки.
- FreeBASIC может собирать и DLL. Отложенный план из передачи 2026-10-06: сборка GUI / Console / DLL, главный файл по #include, разбор ошибок fbc.

## Что выяснить в начале нового чата

1. Версия fbc у пользователя и где лежит (fbc.exe / fbc32.exe / fbc64.exe), 32 или 64 бит.
2. Как выбирать вид результата: GUI (`-s gui`), Console (`-s console`), DLL (`-dll`) — ключ в тексте файла, настройка проекта или переключатель.
3. Главный файл: как у RapidQ (IncOwner, цель проекта) или по `#include` — какой .bas подключает текущий.
4. Формат ошибок fbc: `файл(строка) error N: текст` — проверить на реальном выводе (ParseCompilerLine Borland-формат его, вероятно, разберёт).
5. Нужен ли отладчик (gdb из комплекта FreeBASIC) — или только сборка и запуск.
