# Превью форм в окне View Unit / View Form (unIDE, ветка RQFreeBasic, 2026-10-08)

## Окно списка (DlgListWnd)
- Колонки: «Модуль» и «Форма». В колонке формы пишется «UnitB.dfm (FormB)» (с классом, если он указан в .dpr); для RapidQ — «Form1 (QFORM)».
- Размеры и даты модуля и формы — в подсказке над строкой (ProjectListMouseMove).
- Список перечитывается сам, когда меняется его .dpr на диске: DiskTimerTick → ModListCheckDpr, раз в 2 с.

## Превью (FormPreview.pas, FormPreviewMake)
Форма строится из .dfm так же, как в конструкторе (TReader):
- код формы не выполняется;
- строки Active/Connected, Visible/FormStyle/WindowState/Position/ActiveControl убираются;
- для неизвестного класса берётся аналог из DsgMapClass, иначе ставится панель с именем класса.

Как снимается картинка:
1. Форма вкладывается без рамки в панель превью и ставится за её край (−30000), чтобы у элементов были окна.
2. Элементы обходятся по одному (CaptureByWalk):
   - элементы VCL — WM_ERASEBKGND + WM_PAINT с DC картинки;
   - стандартные окна Windows — WM_PRINT каждому окну.
3. На всё время рисования канва картинки заперта (Canvas.Lock). Без этого VCL освобождал её DC (FreeMemoryContexts), и картинка оставалась одним фоном.

Способы, которые не сработали у пользователя (Windows 7 без Aero):
- PaintTo скрытой формы;
- копия из прозрачного (layered) окна;
- WM_PRINT форме с PRF_CHILDREN.

## Кеш
- Каждая версия .dfm строится один раз, до 640 точек, и хранится в памяти и на диске: dsgcache\<имя>_<crc пути>_<crc времени+размера|4>.preview.jpg.
- Готовое превью показывается сразу. Новое строится через 150 мс после остановки мыши на строке.
- Время построения по журналу — 30–130 мс на форму. В HiLite log пишется строка на каждое построение.

## Ограничения
- Формы, у которых компоненты создаются в коде (например, Unit2 — IDE Options), по .dfm выходят пустыми.
- Превью форм RapidQ нет.
